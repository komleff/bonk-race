# Техническое задание на U2 TugLab

**Назначение:** разработать самостоятельный браузерный стенд для испытания буксировки двух круглых кораблей на основе наработок BonkLab. Адресат — PM, технический планировщик, разработчик и QA. Результат должен позволять играть, менять массу прицепа, сравнивать три сцепки и воспроизводить проблемные случаи.

**Рекомендованное размещение:** отдельное приложение и отдельная сборка внутри `komleff/bonk-race`. Не заменять BonkLab и не создавать долгоживущую альтернативную ветку. Форк всего репозитория для первого выпуска не требуется.

**Целевой адрес:** `https://tuglab.u2game.space/`. В сообщении оператора написано `tuglab.u2game.soace`; здесь предполагается опечатка с учётом существующего домена проекта `u2game.space`. До изменения DNS исполнитель должен сверить точное написание. Сейчас домен и публикация не настроены этой работой.

Это ТЗ подготовлено по поручению оператора; новые детали стенда и выбор размещения представлены для принятия. Документ не объявляет выбранную сцепку утверждённой механикой U2. Эта поставка фиксирует ТЗ в документационном PR; реализация TugLab и публикация сайта ещё не выполнены.

## 1 Цель и состав первого выпуска

Игрок управляет тягачом A, соединяет его с пассивным прицепом B, маневрирует между препятствиями и останавливает прицеп в зоне приёмки. Проверяем, превращается ли инерция груза в понятный навык и какие сцепки/массы дают управляемый результат.

Обязательный объём v0.1:

- Два круглых тела с независимыми координатами, скоростями, массой, ориентацией и вращением.
- Один управляемый тягач с маршевой, обратной, боковой тягой и поворотным моментом; один прицеп без двигателей и Flight Assist.
- Три модели: жёсткая штанга с шарнирами, нерастяжимый гибкий трос, пружина с демпфером и упорами.
- Автоматический выбор ближайшей пары нос/корма при сцеплении, расцепление без телепортации.
- Быстрые массы B: 10, 25, 50, 100, 200, 500, 1000% массы A; независимая настройка радиуса B.
- Полноценное управление с клавиатуры и двумя пальцами на планшете; отдельный тормоз и переключатель FA.
- Открытая площадка, сцены торможения, слалома и парковки.
- Телеметрия обоих тел и сцепки; пауза, один шаг, Restart, экспорт случая и повтор записанного ввода.
- Отдельная статическая сборка, работающая без сервера игры, аккаунта и сети после загрузки файлов.

Не входят: экономическая модель сальвага, станция переработки, повреждение/ремонт кораблей, несколько тягачей, цепочки прицепов, физические сегменты троса, обматывание столбов, лебёдка, разрыв/износ сцепки, сетевой кооператив, полноценное ядро U2 и 3D.

В v0.1 все линии сцепок невесомы и не имеют коллайдера. Препятствия сталкиваются с обоими корпусами. Пересечение линии с препятствием отмечается отдельно: такая сцена ещё не доказывает проходимость материальной штанги или троса.

**Учёт задачи:** `bonk-race-tug` — фиксация ТЗ для ревью; `bonk-race-tow` — будущая реализация, остаётся в очереди.

## 2 Размещение и границы общей базы

### 2.1 Сравнение вариантов

| Вариант | Преимущество | Цена и риск | Вывод |
|---|---|---|---|
| Отдельное приложение внутри `bonk-race` | Общие зависимости, история, проверенные примитивы и один набор исходников | Нужны границы импортов, отдельная сборка и регрессия прежних приложений | Рекомендовано для v0.1 |
| Режим внутри существующего класса BonkLab | Быстро добавить интерфейсный переключатель | Растёт уже крупный оркестратор; сцепка, финиш и управление вмешиваются в старый стенд | Не рекомендовано как основная конструкция |
| Полный форк `bonk-race` | Независимые выпуски, настройки репозитория и публикация | Копируются серверы и инфраструктура гонки; исправления физики/UI нужно переносить между копиями | Пока не оправдан |
| Позднейшее выделение минимального TugLab-репозитория | Независимый инструмент без наследия гонки | Потребуется выделить действительно используемую основу | Возможный следующий этап, если стенд станет постоянным продуктом |

Отдельное приложение в одном репозитории не требует отдельной версии всех пакетов BonkRace. TugLab показывает своё имя, версию стенда и исходный commit сборки. Выпуск BonkRace не повышается только ради изменения настроек испытания, если действующая политика репозитория не требует иного.

### 2.2 Предлагаемые пути

Новые пути — схема размещения для PM/PL; эквивалентные имена допустимы при сохранении границ.

| Путь | Ответственность |
|---|---|
| `client/tuglab.html` | Самостоятельная точка входа |
| `client/src/tuglab/` | Оркестратор, состояние двух тел, ввод, Canvas-рендеринг, интерфейс, сцены, экспорт и воспроизведение |
| `client/src/tuglab/physics/` | Чистый расчёт двух тел, сцепки, контактов и непрерывных проверок; без зависимости от UI и DOM |
| `client/src/tuglab/config/tuglab_defaults.json` | Версионированные настройки стенда и подготовленных сцен |
| `client/vite.config.tuglab.ts` | Независимый build entry и output, без `/api` и серверного proxy |
| `client/dist-tuglab/` | Результат сборки; не используется как папка исходников |
| `docs/tz/spec_u2_tuglab_v0.1.md` | Это ТЗ после принятия и переноса в репозиторий |
| `docs/TugLab-Guide.md` | Запуск, управление, параметры, ограничения и передача случаев |

Полезная общая база: зависимости Vite/Preact/Signals, чистые круговые контактные формулы, инструменты Canvas, RNG и некоторые элементы панели. Не начинать с общего нового фреймворка лабораторий. Небольшое извлечение компонента допустимо только при конкретной пользе и подтверждённом отсутствии изменения старого поведения.

**Запрещённая скрытая зависимость:** TugLab не наследует игровой цикл BonkLab и не импортирует его оркестратор. Изменять общий интегратор или `computeFlightAssist` ради TugLab без отдельного обоснования нельзя. В BonkLab есть автоматическое торможение и прямой угловой предел, не соответствующие нужной семантике U2.

Если изменяется общий модуль, его прежние пользователи должны пройти соответствующие существующие проверки. Изолированные изменения TugLab не требуют разработки тестов чужой серверной экономики.

### 2.3 Сборка и публикация

Предлагаемые новые scripts: `dev:tuglab`, `build:tuglab`, `test:tuglab`, `typecheck:tuglab`. Реальные команды и выбор тестового инструмента определяет PL; эти имена — контракт удобства запуска, а не готовая реализация.

Dev-запуск: отдельный порт, предложено 5174, маршрут `/tuglab.html`; для планшета документируется доступ из локальной сети. Обычные команды BonkRace и BonkLab сохраняются.

Сборка содержит только нужные TugLab HTML/JS/CSS и локальные ресурсы. Она не подключает Colyseus, аккаунт, API гонки, базы данных, аналитику или удалённые CDN во время работы. Относительные адреса ресурсов либо корректный настраиваемый base должны поддерживать размещение под произвольным префиксом. Самодостаточный один HTML и запуск через `file://` не являются требованиями: нужен обычный статический HTTP-сервер.

**В существующем репозитории подтверждён один workflow `deploy-lab.yml`, публикующий BonkLab в корень GitHub Pages.** Независимая вторая Pages-публикация TugLab в тот же Pages site перезапишет этот сайт. Простое копирование второго workflow не допускается. Выделенный поддомен не требует выделенного репозитория: исходники и место публикации — разные решения.

Для `tuglab.u2game.space` рекомендуется отдельный статический сайт на хостинге U2: свой hostname, документный каталог и HTTPS; на том же сервере допустим отдельный virtual host. Не менять существующие сайты и серверы игры. Конкретный хостинг, текущая конфигурация и владелец DNS в этой работе не проверены; исполнитель сначала читает действующий deployment context.

Порядок публикации готовой сборки:

1. Сверить hostname и выбранный статический хостинг. Создать отдельное место публикации, не использовать каталог BonkLab.
2. Настроить DNS: A/AAAA к серверу либо CNAME к адресу выбранного хостинга. Это альтернативы по фактической инфраструктуре, а не три записи одновременно.
3. Выпустить HTTPS-сертификат для точного имени, настроить перенаправление HTTP на HTTPS.
4. Публиковать неизменяемый артефакт конкретной сборки; HTML обновляется вместе с его JS/CSS. Долгий cache допустим для файлов с hash в имени; HTML должен своевременно получать новую версию.
5. Проверить корень, ресурсы, ПК и планшет по настоящему HTTPS-адресу. Проверить, что BonkLab и другие сайты U2 продолжают работать.
6. Сохранить предыдущий полный артефакт для отката. Откат возвращает согласованный набор файлов, а не только HTML.

Для проверки переносимости самостоятельную сборку TugLab также разместить под тестовым вложенным путём. В случае выбора общего GitHub Pages вместо отдельного статического сайта понадобятся единый совмещённый артефакт и уточнённая схема hostname; это другая схема размещения. Готовность сборки не равна факту публикации: выкладка следует после реализации и приёмки артефакта.

## 3 Инварианты движения

1. Масса A учитывается в интеграторе A, масса B — в интеграторе B. Обратная нагрузка передаётся сцепкой; масса B не прибавляется повторно к A.
2. В каждом малом шаге оба тела получают противоположные линейные импульсы и моменты своих креплений.
3. Сцепка не создаёт двигатель, скрытый бонус тяги или бесплатную остановку центра масс.
4. Прицеп не получает Flight Assist, сопротивление среды или стабилизацию от тягача.
5. Корпуса сталкиваются друг с другом даже при активной сцепке.
6. Прямое переписывание позиции/скорости B «следом за A» запрещено. Позиционная коррекция численного ограничения — отдельный ограниченный расчёт, а не игровая телепортация.
7. Окончание ввода снимает ручную команду, но само по себе не обнуляет скорость.
8. Переключение FA не изменяет импульс мгновенно, не меняет массу и не создаёт дополнительные силы.
9. Работа сцепки, контактов и обоих тел рассчитывается в одном временном интервале; нет задержки нагрузки на один основной тик.
10. Физический шаг независим от частоты отрисовки; UI не вычисляет физический исход.

TugLab v0.1 — **ньютоновский исследовательский стенд**, а не альтернативный клиент или physics owner U2. В U2 действует релятивистское shared C#-ядро. Перенос результата требует отдельного PL-плана и серверной проверки; TypeScript-модель не копируется в Unity как production-физика.

## 4 Математический контракт

### 4.1 Состояние и координаты

Для каждого тела: двумерная позиция \(x\) в м, скорость \(v\) в м/с, импульс \(p\) в кг·м/с, курс \(\theta\) в рад, угловая скорость \(\omega\) в рад/с, угловой импульс \(\ell\), масса \(m\) в кг, радиус \(R\) в м, инерция \(I\) в кг·м². Одни величины могут вычисляться из других; два независимо изменяемых противоречивых значения импульса и скорости не допускаются.

Физическая плоскость имеет правую систему координат: нос \(e=(\cos\theta,\sin\theta)\), положительный угол против часовой стрелки. Инверсия экранной вертикали выполняется только в отрисовке. Углы, градусы UI и направления клавиш не смешиваются внутри физического расчёта.

В v0.1 корпус — диск:

\[
I_i=\kappa_i m_iR_i^2,\qquad \kappa_i=0{,}5\ \text{по умолчанию}.
\]

Изменение радиуса и массы меняет инерцию; сила/момент двигателей A от этого не повышаются. Эта формула не заменяет принятый расчёт инерции геометрического корпуса U2.

Крепления относительно центра:

\[
a_i^{nose}=R_ie_i,\quad a_i^{tail}=-R_ie_i,
\quad P_i=x_i+a_i.
\]

Для выбранной пары:

\[
d=\|P_B-P_A\|,\quad n=(P_B-P_A)/d,
\]
\[
u_i=v_i+\omega_i a_i^\perp,\quad
q=(u_B-u_A)\cdot n,\quad a^\perp=(-a_y,a_x).
\]

\(q>0\) означает растяжение. Условия захвата используют полную относительную скорость креплений \(\|u_B-u_A\|\), а не только её радиальную часть.

### 4.2 Передача импульса

При подписанном импульсе \(J\), положительном для натяжения:

\[
\Delta p_A=Jn,\quad \Delta p_B=-Jn,
\]
\[
\Delta\ell_A=J(a_A\times n),\quad
\Delta\ell_B=-J(a_B\times n).
\]

Эффективная обратная масса вдоль сцепки:

\[
w=\frac1{m_A}+\frac1{m_B}
+\frac{(a_A\times n)^2}{I_A}
+\frac{(a_B\times n)^2}{I_B}.
\]

В ньютоновском стенде \(v=p/m\), \(\omega=\ell/I\). Сцепка меняет относительную скорость как \(\Delta q=-wJ\). Суммарный линейный импульс от неё не меняется. Для общего углового импульса учитываются движение центров и собственное вращение.

### 4.3 Три типа сцепки

| Тип | Ограничение и усилие | Обязательная реакция |
|---|---|---|
| Штанга | \(d=L\), подписанный импульс любого знака | Тянет и толкает; шарниры позволяют изменять относительный курс |
| Трос | \(d\le L\), накопленный тяговый импульс \(J\ge0\) | Не создаёт сжатия; провисший трос не тянет, пока не достигается предел |
| Пружина | \(s=k(d-L_0)+c_dq\), \(L_{min}\le d\le L_{max}\) | Растягивается/сжимается, гасит осевые колебания; упоры передают импульсы обоим телам |

Штанга не фиксирует взаимный угол и не сваривает корпуса. Нулевая длина шарнира не входит в первый выпуск.

Трос реализуется одним ограничением расстояния, без физических звеньев. Его визуальный провис не создаёт дополнительной массы или контакта. Учитывается достижение границы внутри малого шага; нельзя тянуть далеко провисший трос преждевременно. В итерационном расчёте ограничивается суммарный накопленный импульс, а не каждая поправка отдельно.

У пружины положительная \(s\) тянет крепления друг к другу, отрицательная раздвигает. Демпфер рассеивает относительную энергию:

\[
E_{spring}=\tfrac12 k(d-L_0)^2,\qquad
\dot E_{diss}=-c_dq^2.
\]

Для начальной настройки через эталонные частоту и затухание:

\[
k=\mu_{ref}(2\pi f)^2,\qquad
c_d=2\zeta\mu_{ref}(2\pi f),\qquad \mu_{ref}=5000\ \text{кг}.
\]

После выбора пресета физические \(k,c_d\) сохраняются при изменении массы B и ориентации. Автоматическая перенастройка жёсткости под новый груз в v0.1 отсутствует: сравниваем одинаковое оборудование.

Жёсткие упоры не являются обрезанием координат. Нижний упор действует толкающим импульсом, верхний — тяговым. Значение максимальной длины не отменяет саму пружину внутри диапазона.

При \(d<10^{-6}\) м нормаль берётся из последней корректной геометрии; при её отсутствии резервное направление фиксировано в физической системе координат. Все деления на массу/инерцию имеют валидные положительные входы; невалидное состояние обрабатывается по §10.

### 4.4 Устойчивость и контакты

Фиксированный основной шаг по умолчанию 1/60 с; четыре малых шага, исходно восемь проходов сцепки/контактов на малый шаг. Дополнительная конфигурация — 1/30 с с тем же числом подшагов. Это исходные параметры: PL может изменить численный бюджет с повторной проверкой AC.

Выбор решателя принадлежит PL. Обязательные свойства: совместное обновление двух тел, корректные моменты креплений, устойчивое сочетание пружины с контактами, повторная проверка ограничений после контактов, отсутствие двойного приложения импульса по числу итераций. Применить устойчивое мягкое ограничение или эквивалентную неявную схему; наивная сила жёсткой пружины без проверки энергии не принимается.

Корпуса и препятствия — гладкие круги; контактного трения нет. Нормальный контакт сам по себе не создаёт вращение диска. Упругость по умолчанию 0,10. Ограниченное исправление проникновения не создаёт бесконтрольный прирост скорости.

Нужна непрерывная проверка движения кругов относительно друг друга и статических кругов. Готовые контакты BonkLab дискретны; одни подшаги не являются доказательством отсутствия туннелирования. При нескольких контактах в одном шаге решатель ограничивает работу и оставляет видимую диагностическую причину, если заявленные допуски не достигнуты.

Объявленная область обязательной численной приёмки: массы B 0,1–10 масс A, радиусы B 2–12 м, длины сцепок 2–24 м, скорости каждого тела до 100 м/с, до 30 статических круговых препятствий. Диапазон включает подготовленные старты и ручной захват. За пределами скоростного диапазона выводится «Вне проверенного диапазона»; скорость не обрезается скрыто. Все стандартные сцены и их автоматические прогоны должны оставаться внутри заявленной области.

## 5 Управление двигателями и Flight Assist

### 5.1 Команды

Управление передаёт независимые доли продольной тяги, боковой тяги и поворотного момента в диапазоне от −1 до +1. Положительная продольная команда использует маршевую силу; отрицательная — ретро. Стик не задаёт мгновенную скорость или полёт к мировой точке.

| Действие | ПК | Планшет landscape |
|---|---|---|
| Марш / ретро | W / S | Вертикаль левого стика |
| Боковая тяга | A / D | Горизонталь левого стика |
| Поворот влево / вправо | Q / E | Горизонталь правого органа управления |
| Тормоз | Удержание Space | Удержание BRAKE возле левого стика |
| FA ON/OFF | F, однократно | Кнопка FA возле левого стика |
| Сцепить/Отцепить | Enter, однократно | Action справа возле органа поворота |
| Пауза | P | Кнопка тулбара |
| Restart | R при фокусе поля | Кнопка тулбара |

Вверх левого стика означает направление носа, вправо — правый борт. Q и отклонение правого органа влево означают визуальный левый поворот; E — правый. Внутренний знак математического угла согласуется с инверсией вертикали Canvas, а не угадывается по имени клавиши.

Вертикаль правого органа игнорируется. Pitch, roll, наклон устройства и отдельный осмотр камеры не входят в TugLab v0.1. Следящая камера позволяет видеть оба тела; изменение масштаба не переназначает оси.

На диагонали левый стик выдаёт независимые компоненты; после круговой мёртвой зоны они линейно нормируются к единичному кругу. Начальная мёртвая зона 0,10, рабочий радиус стика 70 CSS px. Для правой оси мёртвая зона 0,10 и полный ход 70 CSS px. Эти параметры можно править в конфиге; после отпускания команда сразу равна нулю.

### 5.2 FA и накат

FA ON и FA OFF сохраняют одинаковые физические двигатели и угловую стабилизацию. **В обоих режимах отпускание продольной тяги сохраняет продольный накат.** Это существенное отличие от существующего мышиного управления BonkLab.

FA OFF: при отсутствии бокового ввода автоматической боковой силы нет. FA ON: при отсутствии бокового ввода боковой снос гасится доступными боковыми двигателями. Предложенное комфортное ускорение гашения — 4 м/с²:

\[
a_{lat}=\min(F_{lat}/m_A,\ a_{comfort},\ |v_{lat}|/h),
\]

сила направлена против боковой скорости. При нулевой доступной боковой тяге сила равна нулю. Во время ручного стрейфа автоматическая компенсация этой оси не добавляется.

При нейтральной команде yaw вращение A гасится физическим моментом; первоначальное время остаточного гашения 1 с. При полном ручном повороте доступен полный момент ниже мягкого углового предела 80°/с. Момент демпфирования ограничен установленным моментом двигателей и не увеличивается из-за тяжёлого прицепа. Внешнее превышение углового предела гасится доступным моментом, а не прямой записью угловой скорости.

B остаётся пассивным: никакой FA, углового предела, стабилизации, тяги или скрытого сопротивления для него нет.

### 5.3 Тормоз

BRAKE имеет приоритет над ручной продольной/боковой тягой и yaw, действует только при удержании, не переключает FA. Поэтому нельзя обещать одновременный обход груза и ручной поворот под удерживаемым BRAKE: для такого манёвра используются ручная ретро/боковая тяга и поворот.

Тормоз использует максимально доступные силы, противоположные компонентам скорости A в корпусных осях. Для осевой компоненты предел силы последнего малого шага:

\[
|F_{brake,axis}|=\min(F_{available,axis},\ m_A|v_{axis}|/h).
\]

Для yaw аналогично используется максимум доступного противомомента с ограничением последнего шага \(I_A|\omega_A|/h\). Это предотвращает обратный разгон двигателем при торможении собственного состояния A. Внешний импульс прицепа может снова сдвинуть или повернуть A; тормоз не отменяет эту физику и не останавливает B напрямую.

Отпускание BRAKE возвращает актуальное состояние ещё удерживаемых органов ввода. Завершённое касание и старая команда не восстанавливаются. Action и FA не повторяются автоматически от удержания или синтетического мышиного события.

### 5.4 Владение вводом

Два пальца могут одновременно управлять перемещением и yaw. Каждое касание закрепляется за органом, где началось; пересечение другого органа его не запускает. Touch-cancel, отпускание за пределами элемента, потеря фокуса, смена ориентации или режима ввода снимают соответствующую команду.

Клавиатурные команды не перехватываются, когда фокус находится в числовом поле/импорте. Открытие панели настройки, импорт, Restart и скрытие вкладки сбрасывают ввод. Возвращение на вкладку оставляет симуляцию на паузе до явного продолжения.

После большой задержки кадра более 250 мс стенд ставится на паузу; пропущенное время не наверстывается множеством неизвестных игроку шагов. Во время паузы физический таймер не идёт. Один шаг выполняет один основной физический тик со всеми подшагами.

Для проверки законов сохранения есть диагностический параметр отключения всех двигательных сил и стабилизации. Он явно показывает «Диагностика» и не называется FA OFF U2.

## 6 Захват и расцепление

До захвата выбирается ближайшая пара среди нос–нос, нос–корма, корма–нос, корма–корма. При разнице дистанций не более \(10^{-6}\) м применяется этот фиксированный порядок. Подсветка показывает именно ту пару, которую возьмёт Action.

Условия сцепления:

- Корпуса не пересекаются; отрезок между креплениями не проходит через внутренность A, B или статического препятствия.
- Длина между креплениями в диапазоне 2–12 м.
- Полная относительная скорость креплений не больше 2 м/с.
- Все параметры и состояние конечны и валидны.

Если ближайшая пара не подходит, Action показывает конкретную причину: «Слишком далеко», «Слишком близко», «Снизьте относительную скорость», «Крепления перекрыты» или «Некорректное состояние». Нет скрытого перехода на более далёкую пару, автоповорота или автополёта.

Захват фиксирует идентификаторы креплений. Для штанги/троса длина, для пружины свободная длина равны текущему расстоянию. Начальные упоры пружины задаются долями этой фактической длины. Параметр длины в панели определяет геометрию подготовленного старта; после ручного захвата HUD показывает фактическую длину оборудования. Сохранённый случай содержит обе величины, когда они различаются.

Первый расчёт сцепки может передать честный импульс от остаточной относительной скорости. Нет принудительной установки общей скорости или курса. Пружина на ручном захвате не получает заранее накопленную энергию.

При расцеплении сохраняются положения, линейные и угловые скорости. Для v0.1 оставшаяся энергия пружины списывается в размыкание без дополнительного пинка; это явно описанная условность стенда. Повторный захват снова проверяет все условия.

Смена типа сцепки, массы, радиуса, длины, жёсткости, сцены или численного шага применяется только через Restart. Просмотр параметров не меняет физику текущей попытки. Кнопка применения показывает, что попытка будет начата заново; это обычное действие стенда, не отдельный запрос разрешения разработчику.

## 8 Подготовленные сцены и доставка

Во всех сценах отключены зоны льда/грязи/турбо, wall-thrust, шипы, гибель, knockback, свободные орбы и гоночные бонусы. Препятствия невесомыми не являются: они статичны, создают обычный контакт с обоими телами.

| Сцена | Начало и задача | Зачем |
|---|---|---|
| Знакомство | Равные тела в покое, пружина, корма A — нос B, уже сцеплены; открытое пространство | Сразу почувствовать груз без подготовки |
| Захват | Те же тела, расцеплены, расстояние креплений 8 м | Проверить Action, подсветку и отказы |
| Прямое торможение | Общая скорость 25 м/с; отдельный вариант 50 м/с; свободный прямой участок | Сравнить торможение трёх сцепок |
| Обход груза | Тот же скоростной старт; задача остановиться ручным манёвром без удара A–B | Проверить ретро, стрейф, поворот и обучение |
| Слалом | Детерминированная последовательность столбов, старт в покое, цель в конце | Проверить геометрию всей связки |
| Приёмка | Открытый подход и зона радиусом \(3R_B\), стартовая скорость 10 м/с | Проверить остановку прицепа и вращения |
| Диагностика | Выбираемые четыре пары креплений, вращающийся B, внеосевой удар и высокоскоростной контакт | Воспроизводить математические границы |

У тормозных сцен не менее 2000 м свободного пути впереди. При массе B=1000% и ретро A=100 000 Н идеальное торможение с 50 м/с занимает 55 с и 1375 м; это не должно упираться в границу карты до остановки.

Для слалома PL фиксирует геометрию в сцене/seed; в проходимом эталонном варианте свободные зазоры не меньше диаметра самого большого B плюс 4 м. Изменение массы не меняет трассу. Изменение радиуса не расширяет ворота автоматически — размерная трудность должна быть заметна.

На каждом основном тике зона приёмки проверяет:

\[
\|x_B-x_{bay}\|+R_B\le R_{bay},\quad
\|v_B\|\le0{,}5\ \text{м/с},\quad
|\omega_B|\le5^\circ/\text{с}.
\]

Все условия удерживаются непрерывно 2 с физического времени. Нарушение любого условия сбрасывает накопленное время. Сцепка может оставаться подключённой. Касание финиша тягачом не завершает доставку.

При успехе стенд фиксирует результат и ставится на паузу; «Продолжить» сохраняет возможность отцепить груз. Метрические результаты: физическое время, число контактных эпизодов A–B и с препятствиями, максимальная скорость сближения, максимальная нагрузка сцепки и пересечения её линии с препятствиями. Формулы повреждения и общей «оценки пилота» отсутствуют.

Контактный эпизод — начало соприкосновения конкретной пары после отсутствия контакта в предыдущем основном тике. Повторные итерации одного контакта не увеличивают счётчик. Максимальные импульсы считаются по накопленному результату физического контакта, а не по сумме многократных расчётных поправок.

## 9 Интерфейс и визуализация

Первый экран сразу открывает «Знакомство»: пружина, равные массы, FA OFF. Основное поле занимает большую часть landscape-экрана. Настройки физики доступны в сворачиваемой панели, которая ставит симуляцию на паузу.

Постоянный тулбар: «U2 TugLab», сцена, три типа сцепки, быстрые массы, Restart, Pause, Step, Export, Import. Не перегружать его всеми параметрами; на планшете кнопки и быстрые массы могут занимать две строки или раскрывающуюся группу.

На поле различимы A и B, их нос/корма, векторы скорости обоих тел, связь и зона приёмки. Цвет сопровождается формой/подписью. У пружины различимы натяжение, сжатие и упор; у троса — натянут/провис. Длина визуальной пружины не является её физическим числом витков.

Основная телеметрия: масса B/A, скорость A/B, FA, тормоз, состояние сцепки, текущая/свободная длина и число ударов A–B. Расширенная: угловые скорости, относительная скорость креплений, сила сцепки отдельно от двигателя, энергия пружины, ошибки ограничений, шаг/подшаги, время расчёта.

Камера следует за центром области двух тел и меняет масштаб плавно, сохраняя оба корпуса в поле зрения в обычном диапазоне длины. Движение камеры не меняет физику. При расцеплении камера сохраняет фокус на A; направление к B остаётся видимым. Можно вручную менять масштаб. Скорость и масштаб отрисовки не подменяют единицы физических координат.

Оба тела интерполируются из одного и того же физического времени кадра. Концы сцепки вычисляются по этим отображаемым телам, а не один по физическому, другой по интерполированному состоянию. Restart, импорт и новая сцена синхронизируют предыдущие состояния и очищают следы.

Обязательные проверки компоновки: desktop 1280×720 и landscape tablet 1024×600 CSS px. Начальный минимум области нажатия — 48×48 CSS px; органы не перекрываются. Portrait предлагает повернуть устройство и снимает ввод. Поддержка телефона — последующий этап, не автоматически пройденная проверка.

## 10 Валидация и состояния ошибки

Все числовые параметры проверяются на конечность, единицы, диапазоны и взаимную согласованность. Для пружины: \(0\le L_{min}<L_0<L_{max}\), \(k>0\), \(c_d\ge0\). Для тел: \(m>0\), \(R>0\), \(I>0\). Недопустимы неизвестный тип сцепки, неизвестная версия формата, пересекающийся стандартный старт и противоречивое состояние креплений.

Импорт валидируется полностью до замены текущего состояния. При ошибке текущий случай сохраняется, стенд остаётся на паузе, показывается имя поля и причина. Молчаливое приведение старой версии или обрезание массы не допускается.

При NaN/Infinity либо превышении внутренних расчётных лимитов стенд ставится на паузу, ввод снимается, сохраняются последний валидный старт, записанный ввод и причина остановки. Не респаунить тела и не объявлять ошибку физики игровым проигрышем.

Потеря WebGL не рассматривается: стенд использует Canvas 2D. Ошибка загрузки файла/сборки должна быть видна на экране; отсутствие сервера игры не является ошибкой TugLab.

## 11 Экспорт случая и воспроизведение

Два пользовательских действия: «Экспорт случая» сохраняет исходные условия и настройки текущей попытки; «Экспорт повтора» дополнительно сохраняет команды по основным физическим тикам. Формат JSON, версия схемы 1. В ТЗ задаются семантические поля, а не готовый фрагмент программного кода.

| Группа данных | Что сохраняется |
|---|---|
| Идентификация | Версия схемы, имя/версия TugLab, commit сборки, дата экспорта |
| Мир | Идентификатор сцены, seed, полный список препятствий и зона приёмки; геометрия имеет приоритет над повторной генерацией |
| Тела | Начальные позиции, импульсы или согласованные скорости, курс, вращение, масса, радиус и инерция A/B |
| Двигатели | Силы/момент A, параметры FA и торможения, диагностические отключения |
| Сцепка | Тип, начальный статус, фиксированные идентификаторы креплений, свободная/предельная длина, упоры, \(k,c_d\) на старте попытки; подготовленная и уже существующая на этом старте фактическая длины |
| Расчёт | Физический шаг, подшаги, проходы, контактные параметры и численные допуски |
| Ввод повтора | Номер тика, три нормированные оси, состояние тормоза, однократные команды Action/FA; переключения режима учитываются однозначно |
| Итог | Время, успех/причина остановки, счётчики, максимумы нагрузки/ошибок; отделён от входных условий |

Округление отображения не меняет экспортируемые числа. Настройки стиков сохраняются как контекст ручного опыта; физический повтор использует уже нормированные команды и не зависит от CSS-размера экрана.

При ручном захвате его команда записывается в тик; при подготовленном связанном старте сохраняется начальное состояние сцепки. Ручной ввод во время playback отключён. Stop Playback возвращает стенд на паузу, не добавляя движение; Restart возвращает исходный случай.

Захват, состоявшийся позже начала попытки, не переписывает экспортируемое начальное состояние. Его фактическая длина возникает из геометрии на тике Action и может сохраняться в диагностическом итоге. Импорт не должен превращать изначально расцеплённый случай в уже сцеплённый по финальному состоянию попытки.

Запись начинается с первого тика попытки и ограничена 10 минутами физического времени. При достижении лимита запись прекращается с явным уведомлением; симуляция не меняется. В основной приёмке повтор проверяется в той же сборке и среде, без обещания побитовой идентичности между браузерами/процессорами.

Экспорт не содержит аккаунта, токенов, адресов сервера или персональных данных. Хранение конфигурации между перезапусками браузера необязательно для v0.1; импорт является способом передачи воспроизводимого случая.

## 12 Критерии приёмки

Численные пороги ниже относятся к объявленной области §4.4. Это требования к будущей реализации, не результаты выполненной QA. Для тестов сохранения выключены двигатели и стабилизация; внешних контактов нет.

| AC | Проверка | Условие прохождения |
|---|---|---|
| AC-01 | Независимость приложения | TugLab запускается без серверов/API; существующие BonkLab и гонка работают прежним способом |
| AC-02 | Сборка и ресурсы | Отдельный output загружается из корня тестового HTTP-сервера и вложенного префикса; нет отсутствующих файлов и обязательных внешних запросов |
| AC-03 | Два тела и масса | Пройдено 7 масс × 3 сцепки; силы A и \(k,c_d\) не меняются из-за массы B, нет двойного учёта массы |
| AC-04 | Линейный импульс | Нормированная ошибка суммарного импульса ≤10⁻⁵ за 60 с без внешних сил |
| AC-05 | Общий угловой импульс | Внеосевые сцепки дают моменты обоим телам; общая нормированная ошибка ≤10⁻⁵ за 60 с |
| AC-06 | Разгон | Производная скорости центра масс согласуется с \(F/(m_A+m_B)\) с ошибкой ≤1% |
| AC-07 | Штанга | Тяговый и толкающий импульсы; после тика ошибка длины ≤1% заданной длины |
| AC-08 | Трос | Провисший трос не тянет без достижения предела; нет сжатия; верхняя ошибка длины ≤1% |
| AC-09 | Пружина | Верные знаки силы; затухающая осевая реакция при демпфировании; ошибка упоров ≤1% \(L_0\) |
| AC-10 | Энергия | Без внешней работы механическая энергия не возрастает больше 0,5% за 60 с; численная потеря измерена отдельно |
| AC-11 | Контакты | Связанные корпуса сталкиваются; остаточное проникновение ≤1% меньшего радиуса; удар B влияет на A в том же расчётном интервале |
| AC-12 | Непрерывные контакты | Подтверждены случаи, где круг проходит препятствие между состояниями основного тика, включая относительное движение A/B до 200 м/с |
| AC-13 | Захват и отказ | Все четыре пары, фиксированный выбор, подсветка, границы 2/12 м и 2 м/с; невалидный захват не двигает тела |
| AC-14 | Расцепление | Положения и обе скорости сохранены; после размыкания нет остаточных импульсов решателя |
| AC-15 | ПК | Тяга, стрейф, yaw независимы; BRAKE подавляет их; FA/Action однократны; ввод в панели не управляет телами |
| AC-16 | Планшет | Одновременные перемещение/yaw; вертикаль yaw игнорируется; отмена касания снимает ввод; нет двойного Action от синтетической мыши |
| AC-17 | Накат и FA | Продольный накат в ON/OFF; боковое автоматическое гашение только ON; yaw гасится двигателями в обоих; B не получает FA |
| AC-18 | Тормоз | Использует реальные доступные двигатели A, сам не создаёт обратный разгон; внешний толчок B не обнуляется |
| AC-19 | Restart и переходы | Сброшены оба тела, FA, ввод, импульсы решателя, таймеры, контакты, запись и интерполяция; скрытие вкладки оставляет паузу |
| AC-20 | Доставка | Успех только по B и непрерывным двум секундам условий; нарушение сбрасывает таймер; касание тягачом не завершает сцену |
| AC-21 | Случай и повтор | Export/Import сохраняет геометрию, числа и состояние сцепки; повтор ввода воспроизводит исход в той же сборке/среде |
| AC-22 | Ошибочный импорт | Неизвестная версия, NaN, неверные диапазоны/упоры и противоречивое состояние отказаны; текущий случай сохранён |
| AC-23 | Время и отрисовка | 30/60/120 Гц рендера при одинаковых физических тиках не меняют исход; 30/60 Гц физики дают расхождение контрольных метрик ≤5% |
| AC-24 | Представление | На двух обязательных размерах оба корпуса, управление, FA и нагрузка читаемы; нет прыжка линии от разных интерполяций |
| AC-25 | Публикация при выполнении этапа выкладки | Точный HTTPS-hostname открывает нужную сборку и все ресурсы; HTTP перенаправлен; старые сайты не перезаписаны; полный откат проверен |

Для линейного импульса нормировка: максимум начального \(\|p_A+p_B\|\) и \(m_Av_{ref}\), где \(v_{ref}=1\) м/с. Для углового — максимум начальной величины и \((I_A+I_B)\omega_{ref}+(m_A+m_B)R_{ref}v_{ref}\), где \(\omega_{ref}=1\) рад/с, \(R_{ref}=6\) м. Для энергии знаменатель — максимум исходной энергии и 1 Дж. Эти эталоны не являются силами и не изменяют движение.

Быстрые математические проверки запускаются вне браузера по чистому расчёту, без UI. Ручные проверки выполняются минимум в одном Chromium-браузере на ПК и Chrome на реальном Android-планшете. Отчёт содержит сборку, браузер, устройство, размеры, сцены и результаты; эмуляция touch не заменяет проверку планшета. iPad/Safari и телефон пока не gating.

Производительность: в сцене с 30 препятствиями измерить 120 с после прогрева; записать медиану/P95 времени физического тика, FPS и пропущенные кадры. Начальная цель P95 физики ≤4 мс на проверенном ПК и ≤8 мс на проверенном планшете. Это цель оптимизации, не заявление о всех устройствах; если она не достигнута, результат фиксируется отдельно от корректности и требуется явное решение о допустимом бюджете. Потери фокуса и паузы из замера исключаются.

Качественное игровое испытание не является дополнительным техническим gate: минимум пять игроков, по 10 минут знакомства и одинаковая задача приёмки. Измерить улучшение второй попытки, число ударов и объяснимость ошибки. Результат определяет будущую модель U2; не превращать «весело» в автоматический PASS.

## 14 Связь с U2 и открытые вопросы

Стенд не меняет ADR-0038, отвергавший точки крепления; пользователь поручил исследовать новую модель, а production-принятие требует отдельного оформления. Также не меняется нынешний salvage GDD, где массовые разборные корпуса вскрываются на месте. Буксировка обычных остовов на переработку остаётся отдельным расширением продукта.

Перед переносом выбранного поведения потребуются:

- Принятие модели сцепки, её допустимого тоннажа и последствий перегрузки/размыкания.
- Правила буксировки чужого игрока и согласия на воздействие.
- Подвижная форма остова: текущая физика U2 пропускает часть HP≤0/Stationary/DockingLock сущностей.
- Внешние силы/моменты и расчёт связанной пары в одном shared C#-пути с актуальным \(c'\).
- Сетевое состояние двух тел и сцепки, общий replay, переходы, reconnect, docking и согласованное сглаживание.
- Решение о контактах самой линии, если она должна быть материальной, и отдельная приёмка геометрического контура корпуса.

Ни один из этих production-вопросов не блокирует самостоятельный локальный TugLab; стенд не симулирует других пользователей и не выдаёт результат за проверенную сеть U2.

Разумный триггер выделения отдельного репозитория: TugLab получает свой устойчивый выпускной цикл, владельца и независимые зависимости либо начинает интегрировать C#-ядро/сервер U2. Тогда предпочтительно выделить минимальный инструмент с историей нужных файлов, а не поддерживать форк всей гонки с неиспользуемыми серверами.

## 16 Глоссарий

| Термин | Значение |
|---|---|
| Тягач A | Управляемое тело с двигателями |
| Прицеп B | Пассивное тело, получающее силу от сцепки и контактов |
| Сцепка | Связь двух выбранных креплений с заданным законом силы/ограничения |
| Демпфер | Гашение изменения длины сцепки, а не скорости всей связки |
| Импульс силы | Количество движения, переданное за интервал времени |
| Момент инерции | Сопротивление изменению вращения, зависящее от массы и геометрии |
| Эффективная масса | Реакция конкретного ограничения с учётом перемещения и вращения двух тел |
| FA | Flight Assist, помощь доступными двигателями тягача |
| Yaw | Поворот корабля в двумерной плоскости |
| Подшаг | Меньший интервал внутри фиксированного тика физики |
| Swept-проверка / CCD | Проверка пути между состояниями, чтобы заметить быстрый контакт |
| Накопленный импульс | Итог ограничения в данном расчётном шаге, а не отдельная итерационная поправка |
| Интерполяция | Отрисовка промежуточного состояния между физическими тиками |
| Replay | Повтор движения по начальным данным и записанному вводу |
| Gating AC | Обязательный критерий технической приёмки |
| P95 | Значение, ниже которого лежат 95% измерений |
| Форк | Отдельная копия репозитория с независимым развитием |
| Shared C#-ядро U2 | Общий production-расчёт сервера и клиентского предсказания U2 |
