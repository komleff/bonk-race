## 1. Цель

Заменить изотропное сопротивление среды (`linearDragK`) анизотропной моделью трения, в которой поперечное сопротивление (перпендикулярно направлению блоба) значительно превышает продольное (вдоль направления). Результат: блоб «прилипает» к траектории при нормальном вождении, но уходит в контролируемый дрифт при резких манёврах на высокой скорости.

---

## 2. Проблема

Текущая физика основана на модели движения космического тела в безвоздушном пространстве. Сопротивление среды `F_drag = -m × linearDragK × v` действует одинаково во всех направлениях. Это приводит к неинтуитивному поведению: блоб скользит боком при повороте («Жигули на льду»), не чувствует «сцепления с дорогой», требует активной компенсации через FlightAssist.

Игроки не понимают, почему персонаж двигается так, потому что в реальном мире любой наземный объект имеет сцепление с поверхностью, которое сильнее сопротивляется боковому скольжению, чем движению вперёд.

---

## 3. Требования

### 3.1 Функциональные

- **FR-1:** PhysicsSystem разделяет вектор скорости блоба на продольную (вдоль heading) и поперечную (перпендикулярно heading) компоненты и применяет к ним разные коэффициенты трения.
- **FR-2:** Два новых параметра в конфиге: `forwardDragK` (продольное трение) и `lateralGripMultiplier` (множитель поперечного трения относительно продольного).
- **FR-3:** При `lateralGripMultiplier = 1.0` поведение идентично текущему (обратная совместимость).
- **FR-4:** Параметры `forwardDragK` и `lateralGripMultiplier` задаются на уровне трассы (`TrackConfig`) и переопределяются на уровне поверхности (`SurfaceConfig`).
- **FR-5:** Старый параметр `linearDragK` удаляется из `WorldPhysicsConfig` и заменяется на `forwardDragK` + `lateralGripMultiplier`.
- **FR-6:** Угловое сопротивление `angularDragK` не затрагивается на уровне трассы, но может быть переопределено множителем `angularDragMultiplier` на уровне поверхности.
- **FR-7:** SurfaceConfig содержит 7 параметров: `forwardDragMultiplier`, `lateralGripMultiplier`, `angularDragMultiplier`, `thrustMultiplier`, `turnTorqueMultiplier`, `speedLimitMultiplier`, `zoneThrustN`.
- **FR-8:** FlightAssistSystem применяет `thrustMultiplier` текущей поверхности ко всем выходным силам тяги, `turnTorqueMultiplier` — к моменту поворота, `speedLimitMultiplier` — к проверке лимита скорости.
- **FR-9:** PhysicsSystem применяет `zoneThrustN` как постоянную силу в направлении heading блоба **каждый тик**, пока блоб находится в зоне. Чем дольше блоб в зоне и чем большую площадь зоны он покрывает своей траекторией — тем больше суммарный набор скорости. Это вознаграждает точное прохождение по центру зоны.
- **FR-10:** SurfaceDetector определяет текущую поверхность по позиции центра блоба. При нахождении на границе двух поверхностей — приоритет у поверхности под центром.

### 3.2 Нефункциональные

- **NFR-1:** Добавленный расчёт не должен увеличивать время одного тика PhysicsSystem более чем на 5%.
- **NFR-2:** Поведение детерминировано: одинаковые input-ы на одинаковой трассе дают одинаковый результат на любом устройстве.
- **NFR-3:** Все новые параметры хранятся в конфиге, не хардкодятся.

## 4. Логика работы

### 4.1 Место в пайплайне

Анизотропное трение рассчитывается **внутри PhysicsSystem**, после суммирования всех сил (тяга, FlightAssist) и **перед** интеграцией позиции. Порядок систем не меняется: `FlightAssistSystem → PhysicsSystem → CollisionSystem`.

Внутри PhysicsSystem порядок операций на каждом тике:

```
1. Суммировать внешние силы (тяга из FlightAssist)
2. Применить внешние силы к скорости: vel += F_total / m × dt
3. >>> НОВОЕ: применить анизотропное трение к скорости <<<
4. Интегрировать позицию: pos += vel × dt
5. Интегрировать угловую скорость (без изменений)
```

### 4.2 Алгоритм анизотропного трения

**Вход:** `vel` (вектор скорости после применения сил), `angle` (текущий heading блоба), `forwardDragK`, `lateralGripMultiplier`, `dt`.

**Шаг 1. Вычислить локальные оси блоба:**

```
forwardX = cos(angle)
forwardY = sin(angle)
rightX   = -sin(angle)
rightY   = cos(angle)
```

**Шаг 2. Разложить скорость на компоненты:**

```
vForward = vel.x × forwardX + vel.y × forwardY
vLateral = vel.x × rightX   + vel.y × rightY
```

**Шаг 3. Применить трение к каждой компоненте:**

```
lateralDragK = forwardDragK × lateralGripMultiplier

decayForward = max(0, 1 - forwardDragK × dt)
decayLateral = max(0, 1 - lateralDragK × dt)

vForward' = vForward × decayForward
vLateral' = vLateral × decayLateral
```

Ограничение `max(0, ...)` предотвращает инверсию скорости при очень высоких значениях drag × dt. При 30 Гц и `lateralDragK = 15`: `1 - 15 × 0.033 = 0.5` — корректно. При 30 Гц и `lateralDragK = 40`: `1 - 40 × 0.033 = -0.32` — без max(0) скорость инвертируется.

**Шаг 4. Собрать скорость обратно в мировые координаты:**

```
vel.x = forwardX × vForward' + rightX × vLateral'
vel.y = forwardY × vForward' + rightY × vLateral'
```

### 4.3 Формулы (сводка)

| Расчёт | Формула |
|--------|---------|
| Продольная скорость | `vFwd = dot(vel, forward)` |
| Поперечная скорость | `vLat = dot(vel, right)` |
| Продольное затухание | `decayFwd = max(0, 1 - forwardDragK × dt)` |
| Поперечное затухание | `decayLat = max(0, 1 - forwardDragK × lateralGripMultiplier × dt)` |
| Итоговая скорость | `vel = forward × (vFwd × decayFwd) + right × (vLat × decayLat)` |

### 4.4 Взаимодействие с поверхностями

Если блоб находится на специальной поверхности (лёд, слайм, ускоритель), параметры трения переопределяются множителями поверхности:

```
effectiveForwardDragK = trackConfig.forwardDragK × surface.forwardDragMultiplier
effectiveLateralGripMultiplier = trackConfig.lateralGripMultiplier × surface.lateralGripMultiplier
```

Если блоб не на специальной поверхности — используются базовые параметры трассы.

### 4.5 Взаимодействие с FlightAssist

FlightAssist применяет `thrustMultiplier` и `turnTorqueMultiplier` текущей поверхности к выходным силам:

```
outputThrust = calculatedThrust × surface.thrustMultiplier
outputTorque = calculatedTorque × surface.turnTorqueMultiplier
```

Это означает: на грязи (`thrustMultiplier = 0.5`) двигатель выдаёт вдвое меньше силы; на льду (`turnTorqueMultiplier = 0.5`) повороты ленивые.

Также рекомендуется при тюнинге снизить `thrustLateralN` (силу боковых двигателей drift compensation), потому что анизотропное трение уже берёт на себя основную работу по стабилизации. Конкретные значения подбираются при балансировке.

Компонент FlightAssist «Компенсация бокового дрейфа» продолжает работать: он применяет боковую силу, которая затем обрабатывается PhysicsSystem (включая анизотропное трение). Конфликта нет — оба механизма действуют в одном направлении (гасят боковую скорость).

`speedLimitMultiplier` применяется в FlightAssist при проверке лимита скорости:

```
effectiveSpeedLimit = slimeConfig.speedLimitForwardMps × surface.speedLimitMultiplier
```

На Turbo-зоне (`speedLimitMultiplier = 1.5`) блоб может разогнаться выше обычного лимита. При выходе из зоны лимит возвращается к базовому, и FlightAssist + overspeed damping плавно снижают скорость.

## 5. Данные

### 5.1 Новые параметры конфига

**TrackConfig (уровень трассы):**

| Параметр | Тип | Описание | По умолчанию | Диапазон |
|----------|-----|----------|--------------|----------|
| `forwardDragK` | float | Продольное трение (сопротивление качению) | 0.08 | 0.01–0.50 |
| `lateralGripMultiplier` | float | Множитель поперечного трения | 10.0 | 1.0–100.0 |

**SurfaceConfig (уровень поверхности):**

| Параметр | Тип | Описание | По умолчанию | Диапазон |
|----------|-----|----------|--------------|----------|
| `forwardDragMultiplier` | float | Множитель продольного трения | 1.0 | 0.1–5.0 |
| `lateralGripMultiplier` | float | Множитель поперечного трения | 1.0 | 0.05–5.0 |
| `angularDragMultiplier` | float | Множитель углового сопротивления (вращение) | 1.0 | 0.1–5.0 |
| `thrustMultiplier` | float | Множитель силы тяги двигателя (все направления) | 1.0 | 0.1–3.0 |
| `turnTorqueMultiplier` | float | Множитель момента поворота | 1.0 | 0.1–3.0 |
| `speedLimitMultiplier` | float | Множитель лимита скорости | 1.0 | 0.3–2.0 |
| `zoneThrustN` | float | Постоянная сила в направлении heading блоба, применяемая каждый тик пока блоб в зоне, Н | 0 | 0–50000 |

`zoneThrustN` — дополнительная тяга, действующая на блоб каждый тик нахождения в зоне. Направлена по heading блоба (вперёд). Это означает: чем дольше блоб в зоне и чем точнее он прошёл по ней — тем больше набранная скорость. Скиллованный игрок, зацепивший максимальный сектор Turbo-зоны, получает значительно больше скорости, чем тот, кто задел край. Реализуется в PhysicsSystem как дополнительная сила, суммируемая с тягой от FlightAssist на шаге 1–2 алгоритма.

Множители применяются к базовым параметрам из `TrackConfig` и `SlimeConfig`:

```
effectiveThrust = slimeConfig.thrustForwardN × surface.thrustMultiplier
effectiveTurnTorque = slimeConfig.turnTorqueNm × surface.turnTorqueMultiplier
effectiveSpeedLimit = slimeConfig.speedLimitForwardMps × surface.speedLimitMultiplier
effectiveAngularDrag = trackConfig.angularDragK × surface.angularDragMultiplier
```

`zoneThrustN` суммируется с силами от FlightAssist перед интеграцией скорости:

### 5.2 Удаляемые параметры

| Параметр | Где был | Замена |
|----------|---------|--------|
| `linearDragK` | `WorldPhysicsConfig` | `TrackConfig.forwardDragK` + `TrackConfig.lateralGripMultiplier` |

### 5.3 Пресеты для трасс

**Тренировочные трассы (engine scaling):**

| Трасса | `forwardDragK` | `lateralGripMultiplier` | Ощущение |
|--------|----------------|-------------------------|----------|
| Тренировочная 1 | 0.12 | 30 | «Рельсы», минимум заноса |
| Тренировочная 2 | 0.10 | 20 | Лёгкий дрифт при резких поворотах |
| Тренировочная 3 | 0.10 | 15 | Заметный дрифт, нужен контроль |
| Тренировочная 4 | 0.08 | 12 | Аркадный карт |
| Тренировочная 5 | 0.08 | 10 | Целевое поведение трассы дня |

**Поверхности:**

| Параметр | Normal | Ice | Mud/Slime | Turbo/Boost | Sand |
|----------|--------|-----|-----------|-------------|------|
| `forwardDragMultiplier` | 1.0 | 0.3 | 2.5 | 0.5 | 1.5 |
| `lateralGripMultiplier` | 1.0 | 0.15 | 2.5 | 0.7 | 1.8 |
| `angularDragMultiplier` | 1.0 | 0.3 | 2.0 | 1.0 | 1.3 |
| `thrustMultiplier` | 1.0 | 1.0 | 0.5 | 1.0 | 0.8 |
| `turnTorqueMultiplier` | 1.0 | 0.5 | 0.8 | 1.0 | 1.0 |
| `speedLimitMultiplier` | 1.0 | 1.0 | 0.6 | 1.5 | 0.8 |
| `zoneThrustN` | 0 | 0 | 0 | 15000 | 0 |

**Дизайн-обоснование зон:**

**Ice (Лёд):** скользко, заносы, руль ленивый. Двигатель работает нормально (`thrustMultiplier = 1.0`), но трение минимально — разгон есть, а контроль нет. `turnTorqueMultiplier = 0.5` делает повороты ленивыми. `angularDragMultiplier = 0.3` — после столкновения блоб долго «крутится». Сложная зона для спидранна: опытные проходят на скорости, контролируя дрифт; новички замедляются заранее.

**Mud/Slime (Грязь/Слайм):** вязко, медленно, но точно. Двигатель буксует (`thrustMultiplier = 0.5`), лимит скорости снижен (`speedLimitMultiplier = 0.6`). Зато высокое сцепление (`lateralGripMultiplier = 2.5`) — заносов нет, повороты точные. Зона-наказание: вход = потеря времени. Мотивация объезжать.

**Turbo/Boost (Ускоритель):** постоянное ускорение пока блоб в зоне. `zoneThrustN = 15000` Н даёт при массе 100 кг ускорение 150 м/с² каждый тик. За 10 тиков (0.33 сек) в зоне блоб набирает ~50 м/с дополнительной скорости (с учётом трения). За 20 тиков (~0.67 сек, полное прохождение крупной зоны) — до ~90 м/с. Скорость ограничивается `speedLimitMultiplier = 1.5` → реальный лимит 390 м/с. Пониженное трение (`forwardDragMultiplier = 0.5`) сохраняет набранную скорость дольше после выхода из зоны. Сниженное сцепление (`lateralGripMultiplier = 0.7`) — риск заноса на высокой скорости. Скиллованный игрок, прошедший по центру длинной Turbo-зоны, получает значительно больше скорости, чем тот, кто задел краем.

**Sand (Песок):** промежуточная зона. Замедление, но не критичное. Альтернативный маршрут через песок может быть короче, но медленнее — risk/reward для спидраннеров.

Значение `zoneThrustN` для Turbo подлежит балансировке — начать с 15000 и регулировать по ощущениям. Ключевой критерий: прохождение через среднюю Turbo-зону (~0.5 сек) должно давать ощутимый, но не сломанный прирост скорости (~30–50% от текущей).

## 6. Интеграция

### 6.1 Затрагиваемые модули

| Модуль | Изменение |
|--------|-----------|
| `PhysicsSystem` | Добавить расчёт анизотропного трения + применение `zoneThrustN` каждый тик в зоне + применение `angularDragMultiplier` |
| `FlightAssistSystem` | Применять `thrustMultiplier` и `turnTorqueMultiplier` от текущей поверхности к выходным силам/моментам |
| `WorldPhysicsConfig` / `TrackConfig` | Заменить `linearDragK` → `forwardDragK` + `lateralGripMultiplier` |
| `SurfaceConfig` (новый) | 7 параметров на зону (см. раздел 5.1) |
| `SurfaceDetector` (новый или расширение CollisionSystem) | Определение, на какой поверхности находится блоб (по центру) |
| `balance.json` / конфиг трасс | Обновить параметры, добавить пресеты зон |

### 6.2 Не затрагиваемые модули

| Модуль | Почему не меняется |
|--------|-------------------|
| `CollisionSystem` | Коллизии не зависят от модели трения (но `SurfaceDetector` может использовать её данные) |
| Клиентский рендер | Физика — shared логика |
| Networking / Colyseus | Формат сообщений не меняется |
| Input-система | Ввод не затрагивается |

### 6.3 Миграция с `linearDragK`

При миграции: `forwardDragK = старый linearDragK`, `lateralGripMultiplier = 1.0`. Поведение идентично текущему. Затем `lateralGripMultiplier` повышается до целевого значения (10.0) и тестируется.

### 7.1 Тест-кейсы

| 2 | Блоб стоит, input вперёд, `lateralGripMultiplier = 10.0` | Разгон вперёд идентичен тесту 1 (продольное трение одинаковое) |

| 5 | Блоб на скорости, резкий поворот на 90°, `lateralGripMultiplier = 50.0` | Почти мгновенная смена направления, минимальный занос |
| 6 | Блоб на ледяной поверхности (`lateralGripMultiplier` × 0.15, `turnTorqueMultiplier` = 0.5) | Длинные заносы + ленивые повороты. Поведение ближе к текущему «космическому». |
| 7 | Блоб на липкой поверхности (`lateralGripMultiplier` × 2.5, `thrustMultiplier` = 0.5) | Точное управление, почти нулевой дрифт, медленный разгон |
| 8 | Блоб скользит боком вдоль безопасной стены | Wall-thrust работает (ускорение вдоль стены). Поперечное трение не убивает скольжение мгновенно, т.к. стена удерживает контакт |
| 9 | Блоб стоит, input отсутствует | Никакого движения (трение не создаёт движение, только гасит) |
| 10 | `forwardDragK = 0.5`, `lateralGripMultiplier = 100`, `dt = 1/30` | `decayLateral = max(0, 1 - 50 × 0.033) = 0` — боковая скорость обнуляется за один тик, без инверсии |

| 12 | Блоб проезжает через Turbo-зону за 20 тиков (~0.67 сек, длинная зона) vs 5 тиков (~0.17 сек, задел краем) | Длинное прохождение даёт значительно больше скорости, чем короткое. Skill reward: точная траектория по центру > задеть краем. |
| 13 | Блоб входит в Mud-зону на высокой скорости | Резкое замедление за 2–3 тика из-за `forwardDragMultiplier = 2.5`. Двигатель выдаёт 50% тяги. Блоб «вязнет». |
| 14 | Блоб на Ice-зоне, input повороте | Поворот ленивый (`turnTorqueMultiplier = 0.5`). Занос длинный (`lateralGripMultiplier` × 0.15). Вращение после столкновения долго не гасится (`angularDragMultiplier = 0.3`). |
| 15 | Блоб выходит из Turbo-зоны на обычную поверхность | `speedLimitMultiplier` возвращается к 1.0. FlightAssist + overspeed damping плавно снижают скорость до базового лимита. Нет резкого «клэмпа». |
| 16 | Блоб на границе Ice и Mud | Используется поверхность, в зоне которой находится центр блоба. Мгновенное переключение параметров. |

### 7.2 Edge cases

| Ситуация | Ожидаемое поведение |
|----------|---------------------|
| `lateralGripMultiplier = 0` | Нулевое поперечное трение. Блоб скользит вбок бесконечно. Допустимо для дизайна (ультра-лёд). |
| `lateralGripMultiplier` очень большой (>30 при 30 Гц) | `decayLateral` может стать ≤ 0. Ограничение `max(0, ...)` предотвращает инверсию. Боковая скорость обнуляется за 1 тик. |
| Блоб вращается (angVel ≠ 0) | Heading меняется каждый тик → оси forward/right меняются → анизотропное трение корректно отслеживает текущее направление. |
| Скорость = 0 | Разложение на компоненты даёт vFwd = 0, vLat = 0. Трение ничего не делает. Корректно. |
| Блоб на границе двух поверхностей | Используется поверхность, в зоне которой находится центр блоба. |
| Переход с поверхности на поверхность | Параметры трения меняются мгновенно (без интерполяции). При необходимости можно добавить плавный переход позже (P2). |

### 7.3 Детерминизм

Алгоритм использует только `cos`, `sin`, умножение, сложение и `max`. Все операции детерминированы при фиксированном `dt`. Порядок операций фиксирован. Результат одинаков на всех платформах при одинаковых input-ах.

Требуется: добавить анизотропное трение в существующий тест детерминизма (прогон N тиков → сравнение финальной позиции).

## 8. Взаимодействие с wall-thrust

Wall-thrust (ускорение при скольжении о стену) работает в тангенциальном направлении вдоль стены. Анизотропное трение может конфликтовать: если стена перпендикулярна heading блоба, скольжение вдоль стены = боковое движение = сильное трение.

**Решение:** wall-thrust применяется как сила в PhysicsSystem (шаг 1–2 алгоритма), **до** анизотропного трения (шаг 3). Трение затем частично гасит боковую компоненту этой силы. Это означает: wall-thrust эффективнее, когда блоб скользит вдоль стены «носом вперёд» (продольная компонента сильнее), и менее эффективен при скольжении чисто боком. Это физически интуитивно и поощряет правильную технику.

Если при тестировании wall-thrust окажется слишком слабым из-за поперечного трения — увеличить `wallThrustCoeff` компенсаторно.

## 9. Влияние на Slime Arena (PvP-режим)

Если в будущем анизотропное трение будет перенесено в PvP-режим Slime Arena:

- Слаймы получат «сцепление с дорогой» — более предсказуемое управление.
- Дрифт станет контролируемым инструментом, а не постоянным состоянием.
- Зоны эффектов (Лёд, Турбо) получат физически осмысленное различие через `SurfaceConfig`.
- FlightAssist drift compensation может быть ослаблен, т.к. трение делает основную работу.
- Боевые маневры (разворот для атаки хвостом) станут более предсказуемыми.

Решение о переносе принимается отдельно. В рамках данного ТЗ — только Bonk Race.

## 10. Пресеты BonkLab

### 10.1 Миграция существующих пресетов

Все 6 текущих пресетов BonkLab сохраняются как есть, с изотропным сопротивлением (`lateralGripMultiplier = 1.0`). Пресет «Лёгкий и быстрый» переименовывается.

|---|------------------|----------------|-------------------------|--------------------|
| 1 | Ультралёгкий | Ультралёгкий | 1.0 | Нет |
| 2 | Лёгкий и быстрый | **BonkRace 0.1** | 1.0 | Только переименование |
| 3 | Slime Arena | Slime Arena | 1.0 | Нет |
| 4 | Тяжёлый | Тяжёлый | 1.0 | Нет |
| 5 | Минимальный FA | Минимальный FA | 1.0 | Нет |
| 6 | Космос | Космос | 1.0 | Нет |

При миграции: `forwardDragK = старый linearDragK`, `lateralGripMultiplier = 1.0`. Все 6 пресетов ведут себя идентично текущей версии.

### 10.2 Новые пресеты с анизотропным трением

Три новых пресета, различающихся характером сцепления. Все используют базовые параметры тяги из пресета «BonkRace 0.1» (тот же двигатель), меняется только модель трения.

---

**«Картинг»**

Аналогия: Go-kart на асфальтовой трассе, Mario Kart. Высокое сцепление, резкие повороты, минимум заноса. Блоб «прилипает» к траектории, дрифт возникает только при экстремальных манёврах. Самый дружелюбный к новичкам из трёх анизотропных пресетов.

| Параметр | Значение | Почему |
|----------|----------|--------|
| `forwardDragK` | 0.08 | Стандартное продольное трение — свободный разгон/накат |
| `lateralGripMultiplier` | 15.0 | Высокое сцепление — боковое скольжение гасится за 2–3 тика |
| `angularDragK` | 0.15 | Чуть выше базы — быстрая стабилизация вращения |
| `thrustForwardN` | из BonkRace 0.1 | Без изменений |
| `turnTorqueNm` | из BonkRace 0.1 | Без изменений |
| `comfortableBrakingTimeS` | 2.0 | Быстрое торможение — предсказуемость |
| `restitution` | 0.7 | Чуть менее упругие стены — меньше хаоса после bonk |

Ожидаемое ощущение: «рельсовый» геймплей. Куда повернул — туда поехал. Bonk отскоки предсказуемые. Подходит для тренировочных трасс и казуальной аудитории.

---

**«Ралли»**

Аналогия: Rally-car на гравийной дороге, DiRT Rally в аркадном режиме, Colin McRae. Среднее сцепление, контролируемые заносы на поворотах, ощущение «плывёшь по гравию». Дрифт — основной инструмент прохождения поворотов.

| Параметр | Значение | Почему |
|----------|----------|--------|
| `forwardDragK` | 0.06 | Чуть ниже — дольше сохраняется скорость, выше темп |
| `lateralGripMultiplier` | 7.0 | Среднее сцепление — занос на каждом резком повороте, но быстро стабилизируется |
| `angularDragK` | 0.10 | Стандартная — вращение гасится нормально |
| `thrustForwardN` | из BonkRace 0.1 | Без изменений |
| `turnTorqueNm` | из BonkRace 0.1 × 1.2 | Чуть усилен — для компенсации заноса нужен более отзывчивый руль |
| `comfortableBrakingTimeS` | 3.0 | Среднее торможение — есть инерция, но управляемая |
| `restitution` | 0.8 | Умеренные отскоки |

Ожидаемое ощущение: каждый поворот — микро-дрифт. Блоб «плывёт» на входе в поворот, потом подтягивается к траектории. Опытные игроки используют дрифт для wall-thrust. Баланс между контролем и динамикой. Вероятный кандидат на дефолт BonkRace 0.2.

---

**«Бампер-кар»**

Аналогия: аттракцион «Автодром» в парке развлечений, Bumper Cars. Среднее сцепление + высокая упругость стен + усиленный wall-thrust. Столкновения со стенами — не наказание, а ключевая механика. Весёлый хаос, bonk — это фан.

| Параметр | Значение | Почему |
|----------|----------|--------|
| `forwardDragK` | 0.07 | Среднее — нормальный темп |
| `lateralGripMultiplier` | 10.0 | Хорошее сцепление — между «Картинг» и «Ралли» |
| `angularDragK` | 0.08 | Чуть ниже — блоб дольше крутится после bonk, забавный эффект |
| `thrustForwardN` | из BonkRace 0.1 | Без изменений |
| `turnTorqueNm` | из BonkRace 0.1 | Без изменений |
| `comfortableBrakingTimeS` | 2.5 | Среднее |
| `restitution` | 0.95 | Высокая упругость — мощные отскоки от стен |
| `wallThrustCoeff` | 0.5 | Усиленный (база 0.3) — скольжение вдоль стены даёт ощутимый буст |

Ожидаемое ощущение: управление приятное и отзывчивое, но каждый bonk — событие. Отскоки сильные, блоб может «пинг-понгить» в узких коридорах. Wall-thrust ощутимый — опытные используют стены как ускорители. Название «Bonk Race» звучит буквально. Хороший пресет для демонстрации core-фантазии игры.

## 11. Критерии готовности

- [ ] PhysicsSystem разделяет трение на продольное и поперечное по описанному алгоритму.
- [ ] Параметры `forwardDragK` и `lateralGripMultiplier` читаются из конфига трассы.
- [ ] `SurfaceConfig` содержит все 7 параметров: `forwardDragMultiplier`, `lateralGripMultiplier`, `angularDragMultiplier`, `thrustMultiplier`, `turnTorqueMultiplier`, `speedLimitMultiplier`, `zoneThrustN`.
- [ ] FlightAssist применяет `thrustMultiplier` и `turnTorqueMultiplier` текущей поверхности к выходным силам.
- [ ] FlightAssist применяет `speedLimitMultiplier` текущей поверхности к проверке лимита скорости.
- [ ] PhysicsSystem применяет `angularDragMultiplier` текущей поверхности к угловому сопротивлению.
- [ ] PhysicsSystem применяет `zoneThrustN` как постоянную силу по heading каждый тик нахождения в зоне.
- [ ] При `lateralGripMultiplier = 1.0` и всех surface-множителях = 1.0 поведение идентично текущему (обратная совместимость).
- [ ] При `lateralGripMultiplier = 10.0` резкий поворот даёт короткий контролируемый дрифт (тест 4).
- [ ] Ледяная поверхность даёт длинные заносы и ленивые повороты (тест 14).
- [ ] Грязь замедляет и снижает тягу (тест 13).
- [ ] Turbo даёт нарастающее ускорение — длинное прохождение даёт больше скорости, чем короткое (тест 11–12).
- [ ] При выходе из Turbo-зоны скорость плавно снижается до базового лимита (тест 15).
- [ ] Wall-thrust работает корректно с анизотропным трением (тест 8).
- [ ] `max(0, ...)` предотвращает инверсию скорости (тест 10).
- [ ] Тест детерминизма проходит с новым алгоритмом.
- [ ] Старый `linearDragK` удалён, миграция завершена.
- [ ] Все пресеты зон (ice, mud, boost, sand) заданы в конфиге с рекомендуемыми значениями.
- [ ] BonkLab: пресет «Лёгкий и быстрый» переименован в «BonkRace 0.1» с `lateralGripMultiplier = 1.0`.
- [ ] BonkLab: остальные 5 пресетов (Ультралёгкий, Slime Arena, Тяжёлый, Минимальный FA, Космос) сохранены с `lateralGripMultiplier = 1.0`.

## Глоссарий

| Термин | Определение |
|--------|-------------|
| Анизотропное трение | Модель трения, в которой сопротивление различается по направлениям (продольное ≠ поперечное) |
| Продольное трение (`forwardDragK`) | Сопротивление движению вдоль направления блоба (аналог сопротивления качению) |
| Поперечное трение (`lateralDragK`) | Сопротивление боковому скольжению (аналог сцепления шин с дорогой) |
| `lateralGripMultiplier` | Множитель: `lateralDragK = forwardDragK × lateralGripMultiplier` |
| Heading | Угол направления блоба в мировых координатах (angle) |
| Wall-thrust | Механика ускорения при скольжении о безопасную стену |
| Engine Scaling | Настройка физических параметров по трассам для управления сложностью |
| Decay | Коэффициент затухания скорости за один тик: `v' = v × decay` |
| SurfaceConfig | Набор параметров, определяющий поведение физики на конкретной поверхности |
| SurfaceDetector | Компонент, определяющий, на какой поверхности находится блоб (по центру) |
| `zoneThrustN` | Постоянная сила (Н), действующая на блоб в направлении heading каждый тик нахождения в зоне (Turbo) |
| `thrustMultiplier` | Множитель эффективности двигателя на поверхности (Mud = 0.5 → двигатель буксует) |
| `turnTorqueMultiplier` | Множитель момента поворота на поверхности (Ice = 0.5 → руль ленивый) |
| `speedLimitMultiplier` | Множитель максимальной скорости на поверхности (Turbo = 1.5 → можно ехать быстрее) |
| BonkLab | Тестовый полигон для настройки физики Bonk Race с переключаемыми пресетами |
| Пресет | Набор физических параметров (трение, тяга, упругость), определяющий «характер» вождения |
