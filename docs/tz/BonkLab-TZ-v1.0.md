# ТЗ: BonkLab — Песочница настройки физики движения

## Контекст

Движение персонажа в Bonk Race основано на ньютоновской физике с силовой моделью (F=ma) и системой FlightAssist (FA) — «бортовым компьютером», который преобразует ввод джойстика в тяговые силы и моменты. У системы ~40 параметров в `config/balance.json`. Сейчас единственный способ настроить ощущения от управления — менять JSON, перезапускать сервер и играть в полноценный матч.

**Цель:** создать самодостаточную страницу-песочницу BonkLab, где один персонаж катается по тестовой трассе с полной визуализацией физики и возможностью редактировать все параметры в реальном времени. Подобранные параметры экспортируются в конфиги игры.

**Аудитория:** геймдизайнеры и разработчики команды. Страница передаётся коллегам для самостоятельной настройки.

**Архитектура:** полностью клиентская симуляция, без сервера. Физика работает локально на тех же формулах, что и сервер.

**Сборка:** dev-only. BonkLab — отдельный Vite entry point (`/lab`), не включается в продакшн-сборку игры. Для передачи коллегам собирается отдельно: `npm run build:lab` → один HTML-файл.

## 1. Общая структура страницы

### Точка входа

Отдельный Vite entry point: `http://localhost:5173/lab`

Реализуется через multi-page app в Vite (`vite.config.ts` → `build.rollupOptions.input`). BonkLab — независимая страница со своим `lab.html` и `lab/main.ts`. Не загружает основной клиент игры, не подключается к серверу.

### Компоновка экрана

| Область | Расположение | Содержимое |
|---------|-------------|------------|
| **Игровое поле** | Основная часть экрана | Canvas с персонажем, трассой, визуализацией векторов |
| **Панель параметров** | Боковая панель справа (сворачиваемая) | Группы слайдеров с текущими значениями |
| **HUD-телеметрия** | Верхний левый угол поля | Числовые показатели в реальном времени |
| **Тулбар** | Верхняя полоса | Сброс, Экспорт, Импорт, Пресеты, Seed |

На мобильном устройстве панель параметров открывается по кнопке поверх игрового поля.

## 2. Игровое поле

### 2.1. Тестовая трасса

Генерируется текущим генератором арены. Настраиваемые параметры трассы:

| Параметр | Управление | Описание |
|----------|-----------|----------|
| **Seed** | Числовое поле + кнопка «Rnd» | Seed генератора. Ручной ввод или случайный. При смене — перегенерация трассы. |
| **Ширина карты** | Слайдер | `worldPhysics.widthM` (по умолчанию 1000 м) |
| **Высота карты** | Слайдер | `worldPhysics.heightM` (по умолчанию 1000 м) |
| **Плотность объектов** | Слайдер [0.1 … 3.0] | Множитель количества препятствий и зон. 0.5 = свободная быстрая трасса, 2.0 = тесная медленная. |

Трасса содержит:
- **Стены** (границы карты) — отдельные объекты для проверки отскоков
- **Препятствия-столбы** (pillar) — для обхода
- **Шипованные препятствия** (spike) — для контактного урона
- **Проходы** (passage) — для точного маневрирования
- **Зоны:** лёд, слизь, турбо, лава — для проверки модификаторов

**Стены и зоны ускорения — отдельные объекты.** При необходимости их можно расположить вплотную, чтобы получить ускорение вдоль стен (как у конкурентов), но по умолчанию они независимы.

Никаких других игроков, орбов, сундуков и боевых механик. Только персонаж и геометрия.

**Кнопка Restart:** возвращает персонаж на точку старта, сбрасывает секундомер и запускает обратный отсчёт (3-2-1-GO). Позволяет замерять время прохождения трассы для сравнения настроек.

### 2.2. Редактирование объектов трассы *(спринт 2)*

> Отложено на второй спринт. В первой версии трасса генерируется автоматически и не редактируется вручную.

Планируемый функционал:
- Выделение объекта кликом, перетаскивание, изменение радиуса
- Смена типа (pillar / spike / passage / ice / slime / turbo / lava)
- Редактирование параметров зоны
- Кнопки «+» (добавить) и «×» (удалить)

### 2.3. Визуализация на персонаже

На персонаже отрисовываются четыре элемента:

| Элемент | Цвет | Описание |
|---------|------|----------|
| **Маяк-цель** | Жёлтый круг + пунктирная линия от центра | Точка на карте, куда указывает ввод игрока. Видна при удержании ввода. |
| **Вектор ускорения (FA)** | Зелёная стрелка | Направление и модуль суммарной силы FA (`assistFx`, `assistFy`). Куда «толкает двигатель». |
| **Вектор скорости** | Голубая стрелка | Текущая скорость (`vx`, `vy`). Куда фактически летит. |
| **Вектор FA-коррекции** | Оранжевая стрелка (пунктир) | Вклад компенсации дрейфа и автоторможения (разница между полной силой FA и «чистым» вводом). |

Длина стрелок пропорциональна величине. Масштаб стрелок — отдельный слайдер в тулбаре (чтобы при больших силах стрелки не вылезали за экран).

### 2.4. HUD-телеметрия

Компактная панель в углу экрана:

| Показатель | Формат |
|-----------|--------|
| Скорость линейная | `142 / 260 м/с` (текущая / лимит) |
| Угловая скорость | `85 / 180 °/с` |
| Масса | `100 кг` |
| Угол рассогласования | `12°` (между направлением ввода и вектором скорости) |
| Состояние FA | `Разгон` / `Торможение` / `Дрейф-коррекция` / `Холостой ход` |
| Текущая зона | `Нет` / `Лёд` / `Турбо` / `Слизь` / `Лава` |

## 3. Панель параметров

### Общие правила UI панели

- Параметры организованы в **сворачиваемые группы** с заголовками.
- Каждый параметр: **слайдер + числовое поле ввода**.
- **Диапазон слайдера** указан рядом: `[min … max]`. По умолчанию от 0 до 2-3x текущего значения.
- **Кнопка ⓘ** у каждого параметра — всплывающая подсказка с пояснением, единицей измерения и влиянием на поведение.
- Изменения применяются **мгновенно** при перемещении слайдера (live-режим).

---

Все параметры при старте инициализируются значениями из `config/balance.json`.

### 3.1. Персонаж — Геометрия и масса

| Параметр | Ключ в `balance.json` | Ед. | Диапазон | Подсказка ⓘ |
|----------|----------------------|-----|----------|-------------|
| Масса | `geometry.baseMassKg` | кг | [10 … 500] | Масса персонажа. Влияет на инерцию, радиус и масштабирование сил. При старте инициализируется из `balance.json`. |
| Базовый радиус | `geometry.baseRadiusM` | м | [3 … 30] | Радиус тела при базовой массе. Масштабируется как √(масса). |
| Коэффициент инерции | `geometry.inertiaFactor` | — | [0.1 … 2.0] | Множитель момента инерции (I = factor × mass × r²). Больше = труднее поворачивать. |

### 3.2. Персонаж — Тяга (двигатели)

| Параметр | Ключ | Ед. | Диапазон | Подсказка ⓘ |
|----------|------|-----|----------|-------------|
| Маршевый (вперёд) | `propulsion.thrustForwardN` | Н | [1000 … 100000] | Сила переднего двигателя. Определяет ускорение вперёд: a = F/m. |
| Тормозной (назад) | `propulsion.thrustReverseN` | Н | [1000 … 50000] | Сила заднего двигателя. Меньше маршевого → торможение медленнее разгона. |
| Боковые (стрейф) | `propulsion.thrustLateralN` | Н | [1000 … 50000] | Сила боковых двигателей. Для коррекции дрейфа и стрейфа. |
| Поворотные (момент) | `propulsion.turnTorqueNm` | Н·м | [1000 … 100000] | Крутящий момент поворотных двигателей. Больше = быстрее поворот. |

### 3.3. Персонаж — Лимиты скорости

| Параметр | Ключ | Ед. | Диапазон | Подсказка ⓘ |
|----------|------|-----|----------|-------------|
| Макс. вперёд | `limits.speedLimitForwardMps` | м/с | [50 … 600] | Мягкий лимит. FA мягко тормозит при превышении (не жёсткий clamp). |
| Макс. назад | `limits.speedLimitReverseMps` | м/с | [50 … 400] | Лимит скорости движения задним ходом. |
| Макс. вбок | `limits.speedLimitLateralMps` | м/с | [50 … 500] | Лимит бокового скольжения. |
| Макс. угловая | `limits.angularSpeedLimitDegps` | °/с | [30 … 720] | Лимит скорости вращения. |

### 3.4. FlightAssist — Линейное управление

| Параметр | Ключ | Ед. | Диапазон | Подсказка ⓘ |
|----------|------|-----|----------|-------------|
| Время разгона | `assist.accelTimeS` | с | [0.05 … 3.0] | *Желаемое* время набора скорости. Реальное ограничено тягой и массой (a ≤ thrust/mass). |
| Время торможения | `assist.comfortableBrakingTimeS` | с | [0.5 … 10.0] | *Желаемое* время остановки при отпускании ввода. Также ограничено тягой. |
| Порог ошибки скорости | `assist.velocityErrorThreshold` | — | [0.01 … 0.5] | Минимальная разница скоростей для коррекции FA. Ниже порога — FA не вмешивается. |
| Мёртвая зона ввода | `assist.inputMagnitudeThreshold` | — | [0.001 … 0.1] | Минимальное отклонение джойстика для распознавания ввода. |
| Доля тяги автоторможения | `assist.autoBrakeMaxThrustFraction` | — | [0.1 … 1.0] | Какую долю тяги FA использует для торможения при холостом ходе. 1.0 = полная тяга. |

### 3.5. FlightAssist — Угловое управление (поворот)

| Параметр | Ключ | Ед. | Диапазон | Подсказка ⓘ |
|----------|------|-----|----------|-------------|
| Усиление поворота | `assist.yawRateGain` | — | [0.5 … 20.0] | Множитель отклика поворота. Больше = резче реакция. |
| Угол полного отклонения | `assist.yawFullDeflectionAngleDeg` | ° | [30 … 180] | При каком угле джойстика от носа достигается макс. скорость поворота. |
| Мёртвая зона угла | `assist.angularDeadzoneRad` | рад | [0 … 0.1] | Угол рассогласования, ниже которого FA не поворачивает. Гасит дрожание. |
| Время реакции | `assist.reactionTimeS` | с | [0 … 0.5] | Задержка между вводом и началом поворота. Имитирует инерцию отклика. |
| Время остановки вращения | `assist.angularStopTimeS` | с | [0.05 … 1.0] | За сколько секунд прекращается поворот после отпускания ввода. |
| Усиление углового торможения | `assist.angularBrakeBoostFactor` | — | [1.0 … 5.0] | Множитель скорости остановки поворота (>1 = тормозит быстрее, чем разгоняется). |

### 3.6. FlightAssist — Зона заднего хода

| Параметр | Ключ | Ед. | Диапазон | Подсказка ⓘ |
|----------|------|-----|----------|-------------|
| Угол зоны заднего хода | `assist.reverseZoneAngleDeg` | ° | [0 … 90] | **Новый параметр (заблокирован).** Если джойстик указывает в сектор ±N° от «спины» слайма, вместо поворота — движение задним ходом. 0 = задний ход отключён. |

> **Поле отображается в панели, но недоступно для редактирования** (серое, с иконкой замка). Подсказка ⓘ: *«Новая механика, пока не реализована в движке. Будет доступна в следующем обновлении.»* В текущем коде слайм всегда поворачивается к цели. Реализация — отдельная задача в Beads.

### 3.7. FlightAssist — Компенсация дрейфа

| Параметр | Ключ | Ед. | Диапазон | Подсказка ⓘ |
|----------|------|-----|----------|-------------|
| Включена | `assist.counterAccelEnabled` | вкл/выкл | — | Активная компенсация бокового сноса. Выключение = «дрифт». |
| Порог угла | `assist.counterAccelDirectionThresholdDeg` | ° | [5 … 90] | При каком расхождении вектора скорости и курса включается коррекция. |
| Время коррекции | `assist.counterAccelTimeS` | с | [0.05 … 1.0] | За сколько секунд гасится боковая составляющая скорости. |
| Мин. скорость | `assist.counterAccelMinSpeedMps` | м/с | [0 … 200] | Ниже этой скорости коррекция не работает (чтобы не мешать на малом ходу). |

### 3.8. FlightAssist — Демпфирование

| Параметр | Ключ | Ед. | Диапазон | Подсказка ⓘ |
|----------|------|-----|----------|-------------|
| Гашение превышения скорости | `assist.overspeedDampingRate` | доля/тик | [0 … 1.0] | Какая доля «лишней» скорости гасится за тик. 0 = не гасить. |
| Окно детекции осцилляций | `assist.yawOscillationWindowFrames` | кадров | [4 … 30] | Сколько кадров анализируется для обнаружения рысканья. |
| Порог переключений знака | `assist.yawOscillationSignFlipsThreshold` | шт. | [2 … 10] | Сколько смен направления поворота считаются осцилляцией. |
| Демпфирование рысканья | `assist.yawDampingBoostFactor` | — | [1.0 … 5.0] | Во сколько раз снижается команда поворота при обнаружении осцилляции. |

### 3.9. Окружение (мировая физика)

| Параметр | Ключ | Ед. | Диапазон | Подсказка ⓘ |
|----------|------|-----|----------|-------------|
| Линейное сопротивление | `worldPhysics.linearDragK` | 1/с | [0 … 1.0] | Коэффициент «воздушного» трения. Сила = -dragK × velocity. Больше = быстрее тормозит. |
| Угловое сопротивление | `worldPhysics.angularDragK` | 1/с | [0 … 5.0] | Аналог для вращения. |
| Упругость столкновений | `worldPhysics.restitution` | — | [0 … 1.0] | 0 = полностью неупругое (прилипание), 1 = идеально упругое (полный отскок). |

## 4. Тулбар (управление)

| Элемент | Описание |
|---------|----------|
| **Сброс** | Возвращает все параметры к значениям из `balance.json` |
| **Экспорт** | Открывает текстовое окно с JSON всех изменённых параметров. Можно скопировать или сохранить (Save As в будущем). |
| **Импорт** | Открывает текстовое окно для вставки JSON. При применении — параметры загружаются. |
| **Пресеты** | Выпадающий список: «По умолчанию», «Лёгкий и быстрый», «Тяжёлый и инертный», «Без FA», «Космос» (нулевое трение) |
| **Seed** | Числовое поле + кнопка «Rnd». Смена seed → перегенерация трассы. |

Формат экспорта — объект с изменёнными ключами, который можно напрямую применить к `balance.json`:

```
{
  "slimeConfigs.base.propulsion.thrustForwardN": 35000,
  "worldPhysics.restitution": 0.95,
  "assist.accelTimeS": 0.3
}
```

## 5. Физическая целостность (важные ограничения)

### 5.1. Ньютоновская физика обязательна

Проверено: все параметры FA (`accelTimeS`, `comfortableBrakingTimeS`) — это *желаемые* времена. Реальное ускорение ограничено формулой `a ≤ thrust / mass`. FA вычисляет желаемую силу и обрезает её по доступной тяге. Физика не нарушается.

**Принцип:** персонаж никогда не игнорирует физический интегратор. Все перемещения — только через силы → ускорение → скорость → позиция. Никаких прямых присваиваний координат или скорости.

**Dash (Рывок)** — стартовое умение класса Hunter (GDD-Abilities.md). В текущей реализации он обходит физику (прямая интерполяция позиции). В BonkLab Dash может присутствовать как **объект/бонус на карте** (площадка-катапульта), но реализуется через импульсную силу, а не через прямое перемещение. Игрок всегда подчиняется ньютоновской механике.

### 5.2. Столкновения

Столкновения используют импульсный метод (сохранение импульса), модификация скорости — через `impulse / mass`. Позиционная коррекция пропорциональна обратным массам. Физика не нарушается.

### 5.3. Стены

Текущая проблема: персонаж «прилипает» к стенам вместо отскока. Вероятная причина — `restitution` стен, метод отражения скорости или позиционная коррекция. BonkLab позволит диагностировать это, регулируя `restitution` и наблюдая вектора при контакте со стеной.

## 8. Принятые решения

1. **Физика — в `shared/`.** Согласно GDD v3.0, клиент должен самостоятельно рассчитывать управление и движение, сервер — валидировать. Поэтому физические системы (FA, интегратор, столкновения) выносятся в `shared/`, чтобы исключить расхождения клиент-сервер (проблема, выявленная ещё в проекте U2).
2. **Генерация трассы — быстрый вариант для песочницы.** Полноценный генератор трасс потребует отдельной настройки. Для BonkLab достаточно упрощённого генератора в `shared/` с настройкой плотности объектов (слайдер «Плотность»: от свободных быстрых до тесных медленных трасс).
3. **Сборка — только dev.** Код BonkLab не попадает в продакшн-бандл. Для коллег: `npm run build:lab` → один HTML-файл.
4. **Масштаб стрелок — нормализация.** Каждый вектор нормализуется к своему максимуму (сила/макс.тяга, скорость/лимит). Числовые значения на поле не отображаются — относительная длина достаточна.
5. **`reverseZoneAngleDeg` — отложен.** Поле в панели отображается, но заблокировано с пояснением «новая механика, пока не реализована». Реализация — отдельная задача.
6. **Редактор объектов трассы — отложен на спринт 2.** В первой версии трасса генерируется автоматически.
7. **Инициализация параметров.** При старте все параметры загружаются из `config/balance.json`.

## 9. Открытые вопросы

1. **Стены — баг с прилипанием.** Нужно изучить метод отражения скорости при столкновении со стеной. BonkLab поможет диагностировать через регулировку `restitution`.

## 10. Верификация

1. `npm run dev:client` → открыть `http://localhost:5173/lab`
2. Персонаж управляется джойстиком/мышью, трасса отрисована
3. Видны: маяк-цель, вектор ускорения (зелёный), вектор скорости (голубой), вектор FA-коррекции (оранжевый)
4. HUD показывает скорость, угловую скорость, состояние FA
5. Изменить `thrustForwardN` слайдером → ускорение меняется мгновенно
6. Выключить `counterAccelEnabled` → персонаж начинает дрейфовать
7. Изменить seed → трасса перегенерируется
8. Нажать «Экспорт» → текстовое окно с валидным JSON
9. Вставить JSON через «Импорт» → параметры загружаются
10. Нажать «Сброс» → всё возвращается к `balance.json`

## Глоссарий

| Термин | Определение |
|--------|-------------|
| **BonkLab** | Песочница настройки физики движения Bonk Race. |
| **FlightAssist (FA)** | Бортовой компьютер, преобразующий ввод джойстика в физические силы. Всегда активен. Не нарушает ньютоновскую физику — силы ограничены доступной тягой. |
| **Маяк-цель** | Точка на карте, соответствующая направлению ввода игрока. |
| **Компенсация дрейфа** | Подсистема FA, гасящая боковую составляющую скорости, не совпадающую с курсом. |
| **Демпфирование осцилляций** | Подсистема FA, снижающая рысканье при быстрых сменах направления поворота. |
| **Масштабирование по массе** | Механика, по которой силы тяги изменяются с ростом массы по степенному закону: force × (mass/baseMass)^exp. |
| **Restitution** | Коэффициент упругости столкновения. 0 = неупругое (прилипание), 1 = идеально упругое (полный отскок). |
| **Линейное сопротивление (drag)** | Сила, пропорциональная скорости и направленная против движения. Аналог воздушного сопротивления. |
| **Зона заднего хода** | Сектор позади слайма, при попадании ввода в который слайм пятится назад вместо разворота. Новая механика. |
