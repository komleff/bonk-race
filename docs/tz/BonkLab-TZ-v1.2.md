# ТЗ: BonkLab — Песочница настройки физики движения

**Версия:** 1.2 (актуализировано по итогам Sprint 2, 9 марта 2026)
**Статус:** в разработке

> Изменения относительно v1.1 отмечены как **[v1.2]**.

---

## Контекст

Движение персонажа в Bonk Race основано на ньютоновской физике с силовой моделью (F=ma) и системой FlightAssist (FA) — «бортовым компьютером», который преобразует ввод джойстика в тяговые силы и моменты. У системы ~45 параметров в `config/balance.json`. Сейчас единственный способ настроить ощущения от управления — менять JSON, перезапускать сервер и играть в полноценный матч.

**Цель:** создать самодостаточную страницу-песочницу BonkLab, где один персонаж катается по тестовой трассе с полной визуализацией физики и возможностью редактировать все параметры в реальном времени. Подобранные параметры экспортируются в конфиги игры.

**Аудитория:** геймдизайнеры и разработчики команды. Страница передаётся коллегам для самостоятельной настройки.

**Архитектура:** полностью клиентская симуляция, без сервера. Физика работает локально на тех же формулах, что и сервер.

**Сборка:** dev-only. BonkLab — отдельный Vite entry point (`/lab`), не включается в продакшн-сборку игры. Для передачи коллегам собирается отдельно: `npm run build:lab` → папка `client/dist-lab/`.

## 1. Общая структура страницы

### Точка входа

Отдельный Vite entry point: `http://localhost:5173/lab`

Реализуется через multi-page app в Vite (`client/vite.config.ts` → `build.rollupOptions.input`). BonkLab — независимая страница со своим `client/lab.html` и `client/src/lab/main.ts`. Не загружает основной клиент игры, не подключается к серверу.

### Компоновка экрана

| Область | Расположение | Содержимое |
|---------|-------------|------------|
| **Игровое поле** | Основная часть экрана | Canvas с персонажем, трассой, визуализацией векторов, минимапом |
| **Панель параметров** | Боковая панель справа (сворачиваемая) | Группы слайдеров с текущими значениями |
| **HUD-телеметрия** | Верхний левый угол поля (canvas overlay) | Числовые показатели в реальном времени |
| **Тулбар** | Верхняя полоса | Restart, Seed, Плотность, Сброс, Экспорт, Импорт, Пресеты |

На мобильном устройстве панель параметров скрыта по умолчанию, открывается по кнопке. **[v1.1]** Панель не сбрасывается при внешних изменениях параметров (reset/import/preset) — используется `syncTrigger` вместо remount.

## 2. Игровое поле

### 2.1. Тестовая трасса

Генерируется детерминированным генератором арены (`shared/src/physics/arenaGenerator.ts`). Настраиваемые параметры:

| Параметр | Управление | Описание |
|----------|-----------|----------|
| **Seed** | Числовое поле + кнопка «Rnd» | Seed генератора. Ручной ввод или случайный. При смене — перегенерация. |
| **Ширина карты** | Слайдер [200 … 5000] | `worldPhysics.widthM` (**[v1.2]** BonkLab default: 800 м, balance.json default: 1000 м) |
| **Высота карты** | Слайдер [200 … 25000] | `worldPhysics.heightM` (**[v1.2]** BonkLab default: 10120 м, balance.json default: 1000 м. Максимум слайдера увеличен до 25000 м.) |
| **Плотность объектов** | Слайдер [0.1 … 25.0] | Множитель количества препятствий и зон. **[v1.1]** Участвует в Export/Import через `arena.objectDensity`. **[v1.2]** Max увеличен до 25, default = 5.0 (было 1.0). |

**[v1.2]** BonkLab переопределяет ряд значений из `balance.json` при инициализации (overrides применяются поверх balance.json, сам balance.json не меняется):
- `arena.baseRadius` = 20 м (было 10 м)
- Максимум слайдера base radius = 40 м (было 30 м)

**[v1.1]** Старт расположен внизу карты, финиш — вверху. Финишная линия — чёрно-белая клетчатая полоса (reused из основной игры `client/src/rendering/track.ts`). Стартовая зона — зелёный пунктирный круг с надписью «START».

**[v1.1]** Вокруг точек старта и финиша действует зона исключения радиусом 60 м — препятствия не генерируются в этой области.

Трасса содержит:

- **Стены** (границы карты) — 4 прямоугольных объекта толщиной 10 м
- **Препятствия-столбы** (pillar) — серые круги, **[v1.2]** r = настраиваемый (default: baseRadius = 20 м, см. секцию 3.12)
- **Шипованные препятствия** (spike) — красные круги, **[v1.2]** r = настраиваемый (default: baseRadius = 20 м, см. секцию 3.12)
- **Проходы** (passage) — пунктирные круги, **[v1.2]** r = настраиваемый (default: baseRadius = 20 м), парами с зазором = настраиваемый (default: baseRadius×2×1.2 = 48 м, см. секцию 3.12); **[v1.1]** отдельный параметр `passageRestitution` (по умолчанию 0.5× от основного `restitution`)
- **Зоны:** лёд (голубой), **[v1.2]** грязь (тёмно-коричневый `#6B3A1F`, ранее «слизь» — зелёный), турбо (**[v1.2]** оранжевый `#ff8800`, ранее жёлтый) — полупрозрачные круги с модификаторами
- **[v1.2] Орбы** — подвижные объекты, голубые (cyan `#00cccc`), см. секцию 2.7

> **Лава** указана в v1.0, но **не реализована** в генераторе. Будет добавлена позднее.

**Кнопка Restart:** возвращает персонаж на точку старта, **[v1.2]** сбрасывает таймер к 0 и запускает укороченный обратный отсчёт (только «Go!», 0.8 с, вместо 3-2-1-GO). Позволяет замерять время прохождения трассы для сравнения настроек.

### 2.2. Смерть и респаун [v1.1]

При контакте с шипованным препятствием (spike):

1. Персонаж «замерзает» на 0.8 с (`DEATH_FREEZE_S`)
2. Визуальный эффект: расходящиеся красные кольца + полупрозрачный круг
3. После таймера — респаун на точке старта
4. Полный сброс состояния: позиция, скорость, угол, FA-память (yawSignHistory, lastFaOutput, lastFaState, correctionFx/Fy, currentZone)
5. **[v1.2]** Таймер сбрасывается к 0 (`elapsedTime = 0`) при респауне
6. **[v1.2]** Обратный отсчёт после респауна — только «Go!» (1 фаза, 0.8 с)
7. **[v1.2]** Персонаж развёрнут вверх (угол = -π/2) при старте и после респауна
8. **[v1.2]** Сообщение смерти показывает пройденную дистанцию в метрах и процент прогресса

### 2.3. Минимап [v1.1]

В правом нижнем углу canvas отрисовывается миниатюрная карта:

- Серые точки — препятствия
- Красные точки — шипы
- Цветные области — зоны
- Зелёная точка — старт
- Жёлтая точка — финиш
- Белая точка — текущая позиция персонажа
- **[v1.2]** Cyan точки — орбы
- **[v1.2]** Прямоугольник viewport учитывает асимметричное смещение камеры (65% от верха)

### 2.4. Редактирование объектов трассы *(отложено)*

> Отложено. В текущей версии трасса генерируется автоматически и не редактируется вручную.

### 2.5. Визуализация на персонаже

На персонаже отрисовываются четыре элемента:

| Элемент | Цвет | Описание |
|---------|------|----------|
| **Маяк-цель** | Жёлтый круг + пунктирная линия от центра | Точка на карте, куда указывает ввод игрока. Видна при удержании ввода. |
| **Вектор ускорения (FA)** | Зелёная стрелка | Направление и модуль суммарной силы FA (`assistFx`, `assistFy`). Куда «толкает двигатель». |
| **Вектор скорости** | Голубая стрелка | Текущая скорость (`vx`, `vy`). Куда фактически летит. |
| **Вектор FA-коррекции** | Оранжевая стрелка (пунктир) | Вклад компенсации дрейфа и автоторможения (разница между полной силой FA и «чистым» вводом). |

Длина стрелок нормализована: скорость / speedLimit, сила / thrustForward. Относительная длина достаточна для визуальной оценки.

### 2.6. HUD-телеметрия

Компактная панель в верхнем левом углу canvas:

| Показатель | Формат |
|-----------|--------|
| Скорость линейная | `142 / 260` м/с (текущая / лимит) + цветная полоска (зелёный→жёлтый→красный) |
| Угловая скорость | `85 / 180 °/с` |
| Масса | `100 кг` |
| Угол рассогласования | `12°` (между вектором скорости и курсом персонажа) |
| Состояние FA | `Разгон` / `Торможение` / `Дрейф-коррекция` / `Холостой ход` |
| Текущая зона | `Нет` / `Лёд` / `Турбо` / **[v1.2]** `Грязь` (ранее `Слизь`) |
| Время | `01:23.4` (MM:SS.S) **[v1.1]** |
| **[v1.2]** Дистанция | `Дистанция: XXX м` — пройденное расстояние |
| **[v1.2]** Прогресс | `Прогресс: XX%` — процент прохождения трассы + синяя полоска |

### 2.7. Орбы [v1.2]

Подвижные объекты на трассе — новая механика:

- **Физика:** чистая баллистика (без FA), линейное сопротивление. Масса = density × π × r². Столкновения через существующие функции `collisions.ts`.
- **Визуал:** cyan `#00cccc`. Анимация смерти (при контакте со spike): расходящееся cyan-кольцо `#33ffff`.
- **Генерация:** детерминированная от seed. После уничтожения не респаунятся.
- **Spike kill:** орбы уничтожаются при контакте с шипами (настраиваемо через `orbs.spikeKill`).
- **Auto-sync density:** если `orbDensityManual` = false, плотность орбов автоматически пересчитывается при изменении массы/радиуса персонажа (density = player mass / (π × r²)).

Параметры — см. секцию 3.13.

### 2.8. Камера [v1.2]

- **Смещение:** персонаж расположен на 65% от верхнего края экрана (больше обзора вперёд по ходу движения).
- Прямоугольник viewport на минимапе отражает это асимметричное смещение.

### 2.9. Финиш [v1.2]

- **Детекция:** персонаж должен физически коснуться клетчатой полосы (пересечение по обеим осям X и Y).
- **Оверлей финиша:**
  - Заголовок: «Финиш! Новый рекорд!» (если лучшее время) или «Финиш!»
  - Время прохождения
  - Пройденная дистанция
  - Надпись «Нажмите Restart»
- **Best time:** отслеживается лучшее время; сбрасывается при перегенерации арены (смена seed, размеров, плотности, геометрии объектов).

## 3. Панель параметров

### Общие правила UI панели

- Параметры организованы в **сворачиваемые группы** с заголовками (первые 2 развёрнуты по умолчанию).
- Каждый параметр: **слайдер + числовое поле ввода**.
- **Диапазон слайдера** указан рядом: `[min … max]`.
- **Кнопка ⓘ** у каждого параметра — всплывающая подсказка с пояснением.
- Изменения применяются **мгновенно** при перемещении слайдера (live-режим).
- **[v1.1]** Заблокированные параметры имеют `disabled` на обоих `<input>` + иконку замка + визуальный стиль `opacity: 0.5`.
- **[v1.2]** `handleChange` в LabPanel перечитывает все параметры после применения изменения (auto-sync orb density отражается в UI).
- **[v1.2]** `autoStep` учитывает малые значения min (корректный шаг для параметров с min < 1).

Все параметры при старте инициализируются значениями из `config/balance.json`, **[v1.2]** с учётом BonkLab overrides (секция 2.1).

## 5. Физическая целостность (важные ограничения)

### 5.1. Ньютоновская физика обязательна

Все параметры FA (`accelTimeS`, `comfortableBrakingTimeS`) — это *желаемые* времена. Реальное ускорение ограничено формулой `a ≤ thrust / mass`. FA вычисляет желаемую силу и обрезает её по доступной тяге.

**Принцип:** персонаж никогда не игнорирует физический интегратор. Все перемещения — только через силы → ускорение → скорость → позиция. Никаких прямых присваиваний координат или скорости (кроме респауна на точку старта).

### 5.2. Столкновения

Столкновения используют импульсный метод (сохранение импульса). Позиционная коррекция — 100% разделение пересечения.

**[v1.1]** Passage-препятствия имеют отдельный `passageRestitution` (по умолчанию 0.5× от основного) — мягкие стенки для точного маневрирования.

**[v1.2]** Столкновения с орбами — те же функции из `collisions.ts`. Орбы — подвижные тела с массой (density × π × r²), столкновения взаимные (обмен импульсом).

### 5.3. Death/Respawn [v1.1]

Spike contact → 0.8s freeze → respawn с полным сбросом FA-состояния. Все силы, скорости, история осцилляций и коррекции обнуляются — персонаж стартует «с чистого листа».

**[v1.2]** При респауне таймер сбрасывается к 0. Персонаж развёрнут вверх (угол = -π/2). Обратный отсчёт — только «Go!» (0.8 с).

### 5.4. Турбо-зона [v1.2]

Модель турбо-зоны изменена: вместо множителя скорости (`speedMultiplier`) используется `accelBoost`. При нахождении в зоне к персонажу прикладывается сила = `accelBoost × mass` в направлении текущего вектора скорости. Это обеспечивает физически корректное ускорение с учётом инерции.

### 5.5. Физика орбов [v1.2]

Орбы — чисто баллистические объекты:
- Без FlightAssist
- Линейное сопротивление (drag)
- Масса = density × π × r²
- Детерминированная генерация от seed
- Не респаунятся после уничтожения

## 9. Принятые решения

1. **Физика — в `shared/`.** Физические системы (FA, интегратор, столкновения) вынесены в `shared/`, единый код для клиента, сервера и BonkLab. Исключает расхождения.
2. **Генерация трассы — `shared/`.** Упрощённый генератор с настройкой плотности. Полноценный генератор — отложен.
3. **Сборка — только dev.** `npm run build:lab` → `client/dist-lab/`. Не в продакшн-бандл.
4. **Нормализация стрелок.** Скорость / speedLimit, сила / thrustForward.
5. **`reverseZoneAngleDeg` — заблокирован.** Поле в панели с замком и пояснением. Реализация — bead `bonk-race-sz1`.
6. **Редактор трассы — отложен.** Bead `bonk-race-qp0`.
7. **Параметры из `balance.json`.** Все значения инициализируются оттуда, **[v1.2]** с BonkLab overrides поверх.
8. **[v1.1] 60 Гц.** BonkLab работает на 60 Hz (FIXED_DT = 1/60), сервер — на 30 Hz. Для визуальной плавности.
9. **[v1.1] Death/respawn.** Spike → 0.8s freeze → полный FA reset. Константа `DEATH_FREEZE_S` экспортируется из BonkLab, используется в LabRenderer.
10. **[v1.1] Passage restitution.** Отдельный параметр `worldPhysics.passageRestitution`, по умолчанию 0.5× от основного. Мягкие стенки для маневрирования.
11. **[v1.1] Export = полный конфиг.** `JSON.stringify(lab.params)` — все параметры, не только изменённые. Проще для round-trip.
12. **[v1.1] Density в lab.params.** Ключ `arena.objectDensity` участвует в export/import/reset/preset.
13. **[v1.1] syncTrigger вместо remount.** Toolbar-вызовы (reset/import/preset) не пересоздают Panel-компонент, а синхронизируют значения через prop.
14. **[v1.2] BonkLab overrides.** Дефолты BonkLab отличаются от balance.json (высота 10120, ширина 800, baseRadius 20, density 5). Overrides применяются при инициализации, balance.json не модифицируется.
15. **[v1.2] Пресет «Лёгкий и быстрый» при старте.** BonkLab запускается с пресетом «Лёгкий и быстрый» вместо дефолтных значений.
16. **[v1.2] Active preset tracking.** Dropdown показывает текущий пресет, ручное изменение параметра → «Custom». Cross-component sync panel↔toolbar.
17. **[v1.2] slime → mud.** Полное переименование зоны по всем слоям. Цвет: `#6B3A1F`. HUD: «Грязь».
18. **[v1.2] Turbo = accelBoost.** Сила = accelBoost × mass в направлении скорости. Физически корректнее множителя скорости.
19. **[v1.2] Орбы.** Баллистические объекты без FA, auto-sync density с игроком, детерминированные от seed, не респаунятся.
20. **[v1.2] Настраиваемая геометрия.** pillarRadius, spikeRadius, passageRadius, passageGap — отдельные параметры с перегенерацией арены.
21. **[v1.2] Укороченный countdown.** Только «Go!» (0.8 с) вместо 3-2-1-GO. Быстрее итерация при тестировании.
22. **[v1.2] Timer reset on death.** Таймер обнуляется при смерти — каждая попытка начинается с 0.
23. **[v1.2] Camera offset 65%.** Персонаж смещён вниз экрана — больше обзора впёред.
24. **[v1.2] Finish detection.** Физическое касание клетчатой полосы, оверлей с результатами, best time tracking.

## Глоссарий

| Термин | Определение |
|--------|-------------|
| **BonkLab** | Dev-only песочница настройки физики движения Bonk Race. Не является частью игры. |
| **FlightAssist (FA)** | Бортовой компьютер, преобразующий ввод в физические силы. Не нарушает ньютоновскую физику — силы ограничены тягой. |
| **Маяк-цель** | Точка на карте, соответствующая направлению ввода игрока. |
| **Компенсация дрейфа** | Подсистема FA, гасящая боковую составляющую скорости. |
| **Демпфирование осцилляций** | Подсистема FA, снижающая рысканье при быстрых сменах поворота. |
| **Масштабирование по массе** | Силы тяги × (mass/baseMass)^exp. |
| **Restitution** | Коэффициент упругости. 0 = неупругое, 1 = идеально упругое. |
| **Passage restitution** | **[v1.1]** Отдельный коэффициент для проходов. По умолчанию 0.5× от основного. |
| **Линейное сопротивление (drag)** | Сила = -dragK × velocity. Аналог воздушного сопротивления. |
| **Зона заднего хода** | Новая механика (не реализована). Ввод в сектор позади → движение назад. |
| **DEATH_FREEZE_S** | **[v1.1]** Время замораживания после контакта с spike (0.8 с). |
| **[v1.2] Орб** | Подвижный баллистический объект без FA. Участвует в столкновениях с персонажем и препятствиями. |
| **[v1.2] accelBoost** | Модель ускорения турбо-зоны: сила = accelBoost × mass в направлении скорости. |
| **[v1.2] Грязь (mud)** | Зона замедления (ранее «слизь/slime»). Увеличивает трение, снижает лимит скорости. |
| **[v1.2] BonkLab overrides** | Значения по умолчанию, специфичные для BonkLab, отличающиеся от balance.json. |
