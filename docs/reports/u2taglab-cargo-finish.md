# Зачёт финиша по грузу B

Задача `bonk-race-tug2.12`: по прямому уточнению пользователя обе версии буксировки засчитывают финиш по грузу. TugLab AB, U2TagLab AB и U2TagLab ABC теперь фиксируют результат, когда **центр B пересекает finishPoint.y в направлении к финишу**, из области большего y в область меньшего y. Тягач A впереди и C позади не влияют на зачёт.

Проверяется отрезок движения B между предыдущим и текущим принятым тиком: точка пересечения должна лежать в старой ширине ворот `arena.width * .6`. Перескок тонкой полосы за один тик засчитывается; пересечение вне ширины, движение назад и старт уже за линией не засчитываются. Радиус корпуса не расширяет ворота и не даёт зачёт до пересечения центром. Вычисление доли пересечения масштабировано, чтобы избежать переполнения на больших конечных координатах.

В `BonkLab.ts` обе towing-ветки используют одну проверку. Прежнее накопление финиша по трём корпусам удалено. Обычный BonkLab без буксировки сохраняет старую circle-versus-strip проверку. Таймер, bestTime/isNewRecord и однократная фиксация результата сохранены; ABC по финишу продолжает ставить полёт на паузу и очищать управляющие силы. Controls, camera, assistant и численная физика не изменялись этой задачей.

## Проверка

- RED: 16 новых contract-тестов на исходной логике, 11 ожидаемых падений — ранний финиш по A в обоих AB и отказ засчитать B при C позади в ABC. Лог `.cache/tuglab2-qa/cargo-finish/red.log`.
- GREEN: те же 16 тестов прошли. Затем добавлены два теста с реальным accepted physics-step для TugLab AB и U2TagLab AB; существующие ABC тесты изменены на реальное пересечение B при C позади. Проверяются также reverse/off-span, диагональная точка пересечения, граница ворот, конечный большой overshoot, раннее касание носом, неизменность timer/bestTime после зачёта и сохранение более быстрого предыдущего рекорда.
- Полная свежая regression: **480/480**, 0 failures. Тесты выполнялись из исходной директории, а require compiled modules перенаправлялся только в отдельный output `.cache/tuglab2-qa/cargo-finish/build`. Лог `regression.log`.
- TypeScript-сборка исходного `client/tsconfig.tuglab-test.json` с отдельным outDir прошла. Сборки TugLab и U2TagLab с отдельными outDir также прошли; логи `build-tuglab.log` и `build-u2taglab.log`. Общие compiled caches и штатные built directories не изменялись.
- `git diff --check` прошёл. Первоначальный широкий scratch-run использовал неполный include и копии тестов с неверными fixture paths; эти ошибки оснастки устранены перед итоговым запуском оригинальных тестов. Они не классифицировались как дефекты продукта.

Граница проверки: здесь подтверждён игровой finish gate и регрессии оркестратора. Это не новая калибровка ассистента, полная численная матрица или приёмка всех маршрутов/Android. Независимое ревью и browser QA выполняет PM отдельно.
