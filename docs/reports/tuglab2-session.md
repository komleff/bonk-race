# TugLab-2: ассистент, сессия и запись

Дата: 2026-10-11. Beads: `bonk-race-tug2.2`. Реализация Task2 поверх core `05f91f5`; независимое ревью и закрытие задачи выполняет PM после передачи коммита.

## Публичный контракт

`new TrainSession(config, options?)` принимает `settings`, `scene`, `fa`, `initialState`, `dt`, `appVersion`, `sourceSHA`. Допустимый фиксированный `dt`: `1/30`, `1/60`, `1/120`, независимо от RAF. Начальное состояние paused; стандартная empty-сцена покоится. Масса, круг столкновений и прямоугольная инерция каждого корабля должны соответствовать его профилю; позиции и скорости разрешено задавать без пересборки мира.

Поля: `state`, `settings`, `fa`, `commandC`, `telemetry`, `recording`, `assistantStatus`, `stoppedReason`, `dt`. `recording` сохраняет стабильную ссылку: чтение не клонирует всю историю. Потребитель читает последний `telemetry`, а историю записей использует по необходимости. Методы: `resume()`, `pause()`, `restart()`, `step(inputA, rearBrake=false)`, `setMode(mode)`, `setAssistantSettings(patch)`, `setFA(fa)`, `setConnection(id, connected)`, `setConfig(config)`. Последний разрешён только на паузе и создаёт новую начальную сессию атомарно. `setConnection` возвращает `{ok, reason?}`. `step` возвращает `{accepted, state, commandC, contacts, stopReason?}`.

`InputA = {x, y, magnitude, brake}` — мировое направление и нормированный уровень. `CommandC = {forward:0, retro, lateral, yaw}`. Настройки ассистента: `mode`, `g`, `delay`, `Td`, `Tv`, `Tlat`, `Tyaw`, `epsilon`, `yawDamping`. Режимы: coast/guard/brake. Значения и рабочие границы находятся в `config/assistant_defaults.json`.

Чистые функции записи: `exportRecording`, `importRecording`, `replayRecording`, `recomputeRecording`, `compareRecording`, `exportCSV`, `encodeShare`, `decodeShare`. Идентичность сборки по умолчанию берётся из compile-time defines; тесты передают её явно. Replay вводит готовые команды C без контроллера. Recompute повторно запускает причинный контроллер исходного опыта. Compare сохраняет выбранный режим через исходные mode-события и повторяет тот же ввод A; single физически убирает C/BC. `comparison` сообщает изменение состава, число принятых/исходных тиков, полноту ввода и окна измерений. Короткий источник не порождает выдуманный timeout.

## Причинность и силы

История содержит только начала принятых тиков. Задержка округляется вверх до фиксированного шага; release заднего тормоза проходит через ту же задержку. Пауза очищает команды и историю немедленно. Отсоединение любой связи выключает C до явного выбора режима, включая повторную сцепку. Rejected solver attempt не меняет время, историю или журнал.

У C нет второго FA: собственный обычный mapper команд. Forward всегда 0; coast/g=0/отключённый двигатель/размыкание дают нулевые каналы. Retro не более 25%×g, а 100%×g разрешены только в brake при наблюдаемом через задержку запросе. Lateral/yaw ограничены 50%×g; текущий BC ≥ 1.5l0 блокирует retro. Нулевая yaw-команда не включает скрытое демпфирование. Нормированные команды фиксируются один раз на тик, ориентация корабля учитывается mapper на подшагах. A использует существующие `spaceInputFrame`/`spaceEngineWrench`.

`wrenches` — фактически приложенные полные внешние силы и моменты; `engineWrenches` — отдельно двигатели без сил полей. Оба значения вычислены как среднее с весом по длительности из accepted core `forceSamples`, то есть сохраняют импульс тика. Это не пиковая сила подшага. Данные отвергнутых попыток не попадают в запись. CSV разделяет engine/external и использует SI.

## Метрики

Обе связи имеют расстояние, l0, extension, radial velocity, силу, peak force/extension и счётчики ограничений. Для legacy single точные counts недоступны и представлены `null`. Телеметрия содержит anchors, команды и запрошенные каналы, отдельные времена насыщения retro/lateral/yaw, контакты и импульсы, путь B, скорость центра масс кораблей и минимальный clearance. Clearance измеряется в принятых снимках, а не как непрерывный минимум между ними.

Углы сохраняются непрерывными, включая несколько оборотов. Primary `maxAngleB` — максимум абсолютного отклонения B от НАЧАЛЬНОГО направления A, с учётом начальных ±5°. Текущие B−A/B−C и peak B−C записаны отдельно. Primary `maxLateralB` измеряется от начальной линии A. Совместный поворот A и B не скрывает абсолютное отклонение B.

Тормозной путь начинается при первом запросе brake/rearBrake, исключая путь до него. Остановка требует скорости каждого корабля <1 м/с и |ω|<1°/с непрерывно 2 с после первого тормозного запроса. Timeout — 60 с после этого запроса. Ручной idle без торможения продолжает работать. Автоматическая остановка/timeout очищает живую команду C; принятая последняя команда в журнале остаётся фактической.

## Ограничения записи и импорта

Schema 1 хранит app/build identity, config, initialState, dt, настройки, сцену, FA, события и принятые тики с вводом A, командами C, delayed observations, двумя видами wrench, телеметрией и контактами. Импорт проверяет структуру, конечность, идентичность сборки, согласованность профилей/геометрии и начальную безопасность. Проверяется дешёвая причинная согласованность команд с mode/g/detach и delayed brake request, без повторной физики при parse.

Границы: 32 MiB UTF-8, 14400 тиков и столько же событий, суммарно 256 statics/asteroids/fields мира, глубина 20, 5 млн узлов, строки ≤4096, абсолютное числовое значение ≤1e16. Solver work ограничен: initial substeps ≤128, adaptive ≤4096, iterations ≤128, contact quota ≤4096. Контакты в журнале ограничены произведением quota на принятые solverSubsteps. Опасные id `__proto__`/`prototype`/`constructor` отклоняются до старта; `toString`/`hasOwnProperty` безопасны в словарях сил без прототипа.

Размер и число узлов каждого provisional тика проверяются ДО commit результата. При переполнении сохраняется предыдущий конечный импортируемый префикс, пауза и диагностический stopReason; 8192 байта оставлены для завершения записи. Возобновление требует restart. Увеличения неограниченного import cap нет. Тестовый стандартный опыт 60 с при 120 Гц укладывается в заданные границы; произвольная более насыщенная сессия может остановиться раньше по лимиту записи.

## Сцены и Share

Сцены: empty, braking, turn, passage, failure, disconnect. Braking использует 40/80 м/с, offset B ±0.1RB, угол ±5°, vy ±2 м/с, сохраняя исходный l0. Empty по умолчанию имеет скорость 0; можно явно выбрать 40/80. Passage детерминирован по seed и mirror; уже созданные объекты passage заменяются при повторной инициализации, поэтому собственный Share не дублирует их. Failure поддерживает g0/delay2/lateral0/retro0. Turn/disconnect варианты задают метаданные опыта; ввод поворота и действие размыкания подаются через публичный API потребителем UI/qualification.

Share переносит параметры нового paused-опыта, не произвольный mid-run checkpoint. UTF-8 бюджет — 128 KiB; schema/app/build/config/scene проверяются при decode.
