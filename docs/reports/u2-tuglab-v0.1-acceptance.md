Масса A 40 кг, радиус A 20 м; B/A=0.1/0.25/0.5/1/2/5/10, B radius=20 м, длина=8 м, k=1250 Н/м, ζ=0.5. Штатные FA, тяга, drag, поверхности, генератор и орбы сохранены. Четыре секунды начального ожидания, затем 15 с: вверх / диагональ вправо-вверх / вправо / накат / вверх, по 3 с каждый участок. 1140 основных тиков на прогон; интерполяция вызывается на каждом моделируемом кадре. Это численная игровая QA, без реального Canvas в данной части.

Каждый из 21 случаев повторён с интервалом кадра 1/30, 1/60, 1/120 с при общей физике 60 Гц. Сравнение конечных позиций, линейных/угловых скоростей A/B, длины и всех орбов: максимальная абсолютная разница **0**. Отказов/NaN/самопроизвольных пауз нет. Карта не менялась. Диагностический порог `maxValidatedSpeed` = **100 м/с на тело**, отдельный fixture CCD проверяет **200 м/с относительной скорости**. Все сочетания выходили за диагностический порог. Для масс до 5× первый наблюдаемый переход через 200 м/с происходит при штатном разгоне на 4.4–6.42 с от начала прогона, до статического контакта в этом тике. Это не доказательство причины всех последующих пиков: на них могут влиять сцепка, контакты, орбы и штатный knockback; источник каждого пика отдельно не трассировался. Два лёгких случая достигли 2000 м/с — значения существующего ограничения knockback; источник конкретных пиков отдельно не доказан. Политика скорости/сил сохранена по указанию PM, скрытого ограничения QA не добавляет. **Конечность и отсутствие проникновения в этих случаях не означают физическую валидацию на 2000 м/с.**

Измеряются полный P, орбитальный+собственный L, кинетическая энергия плюс потенциальная энергия пружины. Максимальные нормированные ошибки P=5.58×10⁻¹⁴ и L=5.28×10⁻¹², максимальный прирост энергии **0.01230%**, максимальная относительная ошибка ограничения длины 1.00×10⁻¹⁴. Измеренная итоговая потеря энергии достигает **0.50063%** (в том числе неупругие ограничения троса); она записана отдельно от верхней границы роста 0.5%. Между 30/60 Гц максимальное относительное расхождение COM position/velocity и энергии **0.002563%**, предел 5%. Индивидуальные траектории/углы тел в этот показатель не включены.

## Браузер, интерфейс и performance

Свежая сборка без серверного API проверена на собственном временном HTTP-сервере в `/` и `/nested/tuglab/`. В обоих случаях собственные assets загружаются успешно; внешних запросов, network failures и browser errors нет. Stock BonkLab проверен по его штатному `/bonk-race/lab.html`: towing отсутствует, клавиша W не включает новое управление, экспорт остаётся. Собственный сервер QA закрыт; пользовательский dev `http://localhost:5174/tuglab.html` сохранён.

Реальные UI checks проверили: pause/step 1/60, Restart, расцепление/захват, WASD, снятие тяги при focus/input, пустое числовое поле с alert без изменения значения, k/массу, сохранение карты при tow edits, новый Seed/Rnd/density, мышь/blur, touchStart/touchMove/touchCancel через CDP. Отдельный реальный UI lifecycle поставил QA-шип у B, наблюдал штатную смерть/респаун/Go, старое удержание и autorepeat не восстановили тягу; свежий keydown восстановил управление. Touch здесь — **эмуляция**, не Android.

PNG 1280×720 и 1024×600 самостоятельно просмотрены: A/B, сцепка, миникарта, FA, статус и кнопки читаемы; toolbar переносится на две строки на 1024, canvas ниже него, минимальные tug-кнопки 48×48. Правая панель прокручивается, нижние параметры на 1024 находятся ниже fold. Снимки сделаны у исходного старта на паузе; согласованность интерполяции дополнительно проверяется runtime fixtures и matrix, отдельного визуального измерения ошибки линии в движении нет.

Среда: macOS **26.5.2 (25F84)**, **Apple M3 Pro**, **18 GiB RAM**, Chrome **154.0.8037.97**, Playwright **1.63.0**, **headless**, 1280×720/DPR 1. GPU probe отдельным браузером с теми же параметрами: ANGLE Metal Renderer Apple M3 Pro, driver 26.5.2. Это браузерный рендер на данном Mac, не физический экран/планшет и не измерение под полной нагрузкой пользователя.

После startup countdown и 3 с прогрева измерены **120.0288 с настоящего RAF**. Отдельно обёрнуты actual `lab.tick` (7202 вызова), `lab.update` и интервалы кадра; продолжительность не ускорялась. Использованы реальные keyboard events каждые 3 с (вверх/вправо/накат/влево/накат/вверх/накат), default spring и исходная сцена **42 препятствия/40 зон/30 орбов** (строже исходного количества 30, карту под benchmark не изменяли). Пауза/hidden/failure отсутствуют.
