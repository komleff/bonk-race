# U2TagLab: управление грузом через задний тягач

12 октября 2026, задача bonk-race-tug2.8. Цель пользователя: груз следует уже пройденной траектории ведущего, C своими двигателями служит его тормозом. Исходная геометрия сохранена: все корпуса смотрят вперёд, нос C соединён с хвостом B. Перевёрнутый C ниже — искусственный аварийный fixture, не доказательство неправильного начального расположения в приложении.

## Подтверждённые причины

Старая observation видела только хвост B относительно носа C в системе отсчёта B. Совместный боковой перенос B/C на100м со скоростью10м/с давал lateralError≈0 и lateralVelocity0. Независимый current-flight fixture W5с/D2с/Space3с на seed42/density5 показал небольшую помощь, но не воспроизвёл сильный пользовательский занос: максимум body-side скорости B .177→.128м/с, C остался позади B. Его положительная проекция на мгновенный курс A объясняется поворотом A и отдельно не доказывает настоящий обгон.

Unsigned BC distance/radial velocity меняли смысл после обгона: C впереди B и быстрее него на100м/с получал retro0. Поворот всегда к хвосту B мог развернуть цель C на180°. При искусственном перевороте C сжатая BC давала ретротягу вперёд вдоль курса A, около5.76МН. Наконец, старая помощь при торможении реагировала преимущественно на относительное сжатие BC, не на скорость груза: одинаковые40м/с всех корпусов вызывали всего .104 retro.

## Изменения и контракт

- `assistantPath.ts`: детерминированный `AssistantPathTracker(state)`, `reference(state)`, `accept(state)`. Только принятые положения центра A добавляют геометрические точки с разрешением2м. Ordered progress B ограничивает перескок на будущий виток. Хранится окно8км, обычно не более4002точек. Начальная прямая8км позади A — явно синтетическая опора начального состава, не ранее записанный полёт. По мере движения её заменяет настоящий принятый путь. Если груз остался за окном, reference отсутствует: C ждёт без тяги, физика продолжает полёт; новый старт восстанавливает опору. Пауза/режим не переписывают геометрию.
- `assistant.ts`: поперечная цель C смещена против ошибки B относительно локальной исторической касательной: eBC+2eB, vBC+2vB. Это даёт отдельную реакцию на B-only drift, когда C уже на линии; первая гипотеза eBC+eB алгебраически отменяла эту ошибку и была отклонена отдельным RED. Yaw C следует исторической касательной, не мгновенному курсу A или обращённой назад линии после обгона. Продольный запрос использует знаковые gap и closing velocity вдоль этой касательной. Explicit Brake добавляет скорость B/Tv; Guard сохраняет прежний меньший потолок.
- Observation имеет optional strict `track={tangentX,tangentY,longitudinalVelocityB,crossTrackB,longitudinalDistance,longitudinalClosingVelocity}`. Shape прежних полей/settings/commands сохранена; distance/radialVelocity продолжают описывать фактическую BC-геометрию. Отсутствие принятой reference явно отличается от двухаргументной pure observation: оно не создаёт новую опору по текущему курсу A.
- `commandCWrench(...,dt,track?)`: в каждом реальном подшаге retro блокируется, если текущий нос C направлен против задержанной касательной. Команда может оставаться ненулевой, но actual accepted engine means честно показывают нулевую ретротягу. Прежний stretch guard сохранён отдельно. Никакой силы по скрытой оси, двигателя B, FA C, march C, teleport, нового профиля или изменения solver/tolerances нет.
- `LabTrain.ts` / `session.ts`: tracker обновляется после полного принятого commit; rejected solver/recording step не добавляет путь. Пауза очищает pending команды/реакции, сохраняя принятый путь; Restart создаёт tracker заново. Задержка по accepted simulation time и прежние engine caps/g сохраняются.
- `recording.ts`: optional track проверяется целиком по точным ключам, конечности чисел и единичной касательной. Старые записи без группы могут воспроизводить свои сырые команды без нового safety-контекста; новая группа передаётся и при raw replay. Same-build causal recompute восстанавливает tracker из initialState и принятых A-состояний. Новая версия не обещает пересчёт старой версии controller как идентичного алгоритма.

## RED → GREEN и физические пары

Первоначальные RED: оба знака общего заноса, недоступный past-tangent API, старое наблюдение перед текущим переворотом C, недостаточный rear-brake запрос. Дополнительные RED: явно undefined reference подменялась JS default; B-only error сокращалась; unsigned gap выключал retro после обгона. Actual тесты frozen30d1d6a дали RED на compressed rear-only braking, standard40, заранее выбранной moderate45 curve и B-only skid. Старые модули получены из неизменённого30d1d6a; новая версия использует те же начальные состояния и A input. Ожидание20% снижения ошибки/скорости зафиксировано перед сравнением; caps/evaluator не подгонялись. Одна старая synthetic saturation-проверка обновляет новые signed поля вместе с прежними distance/q, сохраняя все прежние пределы .25/1/.5.

## Проверка и ограничения

Свежие `tsc -p client/tsconfig.tuglab2-test.json` и frontend `tsc --noEmit` PASS. `tests/tuglab2/*.test.cjs`:93/93 PASS, включая21 новый case (pure/physical/path/retry/pause/replay). Игровой адаптер `tests/tuglab/u2taglab-train.test.cjs`:27/27 PASS; host test tsc PASS; npm test PASS (exit0); собственный git diff --check PASS. Все12 standard обеих версий дошли до60с; критерия полного покоя не достигли, включая Brake40 (маленькая скорость B не означает полного покоя по omega всех корпусов). Полная matrix466, браузер/Android и текущая страница пока не квалифицированы этим разработчиком; PM/QA запускают их после заморозки source.

Отрицательные результаты сохранены: Guard40 уменьшает смещение/скорость, но angle относительно старой страховки растёт3.266→7.137rad (накат8.425rad); боковая сила через хвост имеет существенный вращающий момент, поэтому меньшее отклонение пути не означает меньший разворот. Guard80 чуть ухудшает side и чаще допускает обгон; B-only Guard улучшает путь/скорость, но сильнее вращает B; moderate Brake существенно улучшает траекторию, но остаточная скорость почти равна старой и не гарантирует полную остановку. Aggressive90° с полной тягой сохраняет ≈509м ошибки пути и ≈55.64м/с остатка в Brake (старый≈530.74м/97.51м/с); side нового хуже старого. C всё ещё может обогнать B по инерции при слабой страховке. Прежние ограничения двигателей, задержка, массы и геометрия делают невозможной гарантию всех маршрутов/поворотов/состояний. Исправление не объявляет эти случаи спасёнными.
