# Task 1 — совместная физика TugLab-2

Задача `bonk-race-tug2.1`. Только изолированный worktree/ветка `feat/u2-tuglab2`. Старые исходники не менялись.

## Файлы

- `client/src/tuglab2/types.ts`: контракт TrainConfig/State/Connection/sampler/result.
- `config.ts`: каталог U2, независимые корабли/модули, стандарт M–L–M, преобразователь SpaceProfile.
- `train.ts`: безопасный старт, глубокие копии, геометрия креплений с вращением, атомарный захват/расцепка, валидаторы.
- `physics.ts`: общий шаг трёх тел и всех астероидов; симметричные пружинные импульсы, совместная midpoint-матрица демпферов, общий CCD/прогностические ограничители, откаты и диагностика.
- `client/tsconfig.tuglab2-core-test.json`, `tests/tuglab2/physics.test.cjs`.
- Небольшие разделы `.memory_bank/activeContext.md`, `progress.md`, `systemPatterns.md`.

## Интерфейс для следующего этапа

`createDefaultTrainConfig()`, `fitTrainShip(size, passive?)`, `fitTrainLink(module, restLength?)`, `cloneTrainConfig(config)`, `trainSpaceProfile(config,id)`.

`createTrain(config)`, `cloneTrainState(state)`, `trainConnectionGeometry(state,connection)`, `setTrainConnection(state,id,connected)` и `advanceTrain(state,dt,sampler?)`. Геометрия g.radialVelocity/g.relativeSpeed использует скорости креплений, включая omega. TrainState содержит `bodies.A/B/[C]`, `connections`, `config`, `world`, `paused`, `diagnostics`. TrainConfig содержит `composition`, `ships.A/B/C`, `links.AB/BC`, `numerics`, `world`. Поля определены в types.ts.

Sampler получает `{id,body,time,subDt}` для всех ship/asteroid, возвращает `{force,torque}`. Он чистый, читает отдельные копии до применения любых сил. Поля мира и двигатели объединяет потребитель; ядро не добавляет их второй раз. B — пассивный профиль; внешние поля всё же могут давать ему силу. `advanceTrain` выполняет один тик независимо от флага paused, чтобы session поддерживала Step; автотики на паузе блокирует session.

Начало направлено по +X при angle0, A находится в world.spawnPoint, B/C позади. Профили A/C независимы. Скоростные поля speedLimits задают три линейных лимита захвата; при изменении общего speedLimit потребитель синхронизирует соответствующие limits явно. Минимум захвата2м; успешный захват сохраняет фактическую длину, независимо от рекомендации. Короткий допустимый захват не растягивается автоматически. Не помещающийся старт отклоняется без перемещения/изменения профиля.

По согласованному решению PM `single` вызывает read-only `advanceSpaceWorld` ровно один раз. Это обеспечивает точную прежнюю численную опору без изменений старого решателя. Train всегда использует совместный новый решатель. Счётчики `limitActivations` означают ненулевые прогностические импульсы принятых итераций; откаченные пробы не попадают в счётчик. Для legacy-single `limitCountsExact=false`: счётчик недоступен и не должен отображаться как измеренный ноль. `couplingImpulse` знаковый суммарный импульс связи за тик.

Для A/B/C, включая сохранённый C в single: масса/геометрия/выведенные R/I, общий и три линейных лимита, yawLimit, crewGLimit и времена торможения положительны и конечны; тяга/момент/deadzone/lateralComfort неотрицательны и конечны; enginesEnabled имеет boolean-тип. Проверяются seed, плотность, размеры/опорные точки/clearance/clock мира, радиусы площади полей и определения локальных полей, включая конечность/знак коэффициентов и уникальность их ID. ## Принятые силы для записи Task 2

Добавлен экспорт `TrainForceApplied { id, time, subDt, wrench }` и обязательный `TrainAdvanceResult.forceSamples: TrainForceApplied[]`. Это отдельные копии фактически приложенных sampler-сил/моментов в SI для всех динамических тел и принятых подшагов, в порядке sampler-вызовов. Без sampler массив пуст: внешние силы равны нулю. На отказе массива пробных сил нет. Внутренние пружинные/контактные импульсы остаются в прежней диагностике, а sampler может объединять двигатель и поле.

Для train массив принадлежит конкретной попытке и возвращается только после принятия всей транзакции. Для single прежний `advanceSpaceWorld` не менялся: его sampler вызывается ровно один раз для каждого динамического тела на каждом подшаге; полный успешный прогон является последней попыткой. Поэтому wrapper возвращает только суффикс длиной `solverSubsteps * (2 + asteroidCount)`, исключая вызовы неудачных предыдущих попыток. Неуспешный итог возвращает `[]`. Самплер не запускается повторно ради записи, никакая внешняя история при этом не ведётся.

RED: три новых проверки падали из-за отсутствия forceSamples. GREEN: **29/29physics PASS**. Проверены равенство записанного wrench реально приложенному импульсу/вращению, чистота исходного состояния, time/subDt каждого подшага, пустая запись при некорректной силе/бюджетном отказе, отсутствие пробных сил при успешном повторе для train и single. Сценарий restitution1/maxContactEvents1/vA100000 явно вызывает sampler в отклонённой крупной попытке; принятые forceSamples, тела и контакты совпадают с отдельным запуском сразу на принятом дроблении. Исходные контрольные траектории и60с инварианты проходят без изменения физических формул или старых исходников. Core tsc PASS; общий tsc PASS на момент проверки до дальнейших изменений Task 2.
