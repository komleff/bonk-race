# TugLab v0.1 — руководство

TugLab — отдельная статическая оболочка BonkLab с пассивным прицепом B. Исходная карта, препятствия, поверхности, орбы, Flight Assist (FA), камера и финиш по тягачу A сохранены. Сервер игры и API не нужны.

## Запуск

Из корня репозитория:

```bash
npm ci
npm run dev:tuglab
```

Открыть `http://localhost:5174/tuglab.html`. Для самостоятельной сборки:

```bash
npm run build:tuglab
python3 -m http.server 5194 --directory client/dist-tuglab
```

Открыть `http://localhost:5194/`. Передавать весь каталог `client/dist-tuglab`, включая `assets`. Относительные ресурсы поддерживают вложенный URL; HTML открывают через HTTP, а не двойным щелчком. Версия стенда 0.1.0, короткий SHA сборки виден в панели.

## Управление и игра

Нажать на игровое поле, затем использовать WASD или стрелки: направление задаётся в мировых осях. Мышь и сенсорный джойстик работают как в BonkLab. Для остановки ввода отпустить клавиши/мышь/касание. Ввод в поле параметров снимает управление. Потеря фокуса или скрытие вкладки ставит игру на паузу; возвращаться кнопкой «Продолжить».

«Пауза» сохраняет состав, «Step» на паузе выполняет один физический тик 1/60 с. «Restart» возвращает оба тела на свободный старт, сбрасывает ввод, FA, таймеры и интерполяцию; масса демпфирования фиксируется заново. В начале и после смерти работает штатный отсчёт. Гибель A или B возвращает весь состав. Победа определяется штатным финишем A.

«Расцепить» сохраняет положения и скорости тел. «Сцепить» использует имеющиеся крепления: расстояние 2–12 м, относительная скорость точек не более 2 м/с; отказ показан строкой состояния и не перемещает тела. Измеряется скорость креплений с учётом вращения, поэтому близкие неподвижные центры не гарантируют захват.

Панель справа прокручивается; на 1024×600 настройки длины и пружины находятся ниже видимой части. Крестик скрывает панель и освобождает поле. Параметры движения, FA, сопротивления, зон и геометрии A описаны в [руководстве BonkLab](BonkLab-Guide.md). Пресет движения сохраняет настройки `tow.*`, но начинает состав заново. Seed/Rnd/насыщенность меняют карту; настройки прицепа её не меняют.

## Прицеп и сцепка

| Параметр | Диапазон | По умолчанию |
|---|---|---|
| Масса B / A | 0.1–10; быстрые 0.1/0.25/0.5/1/2/5/10 | 1 |
| Радиус B | 2–60 м | 20 м |
| Длина между креплениями | 4–24 м | 8 м |
| Сцепка | Штанга / трос / пружина | Пружина |
| Жёсткость k | 0–10000 Н/м | 1250 Н/м |
| Коэффициент демпфирования ζ | 0–1.5 | 0.5 |

Длина относится к точкам крепления на краях дисков, а не к расстоянию центров. Штанга удерживает целевую длину и передаёт растяжение/сжатие. Трос ограничивает максимальную длину и свободен при провисании. Для пружины это длина покоя; упоры равны 0.5 и 1.5 длины покоя. Больший k даёт более сильное возвращение при том же растяжении; k=0 оставляет только упоры. Демпфер рассчитывается как `c = 2 ζ sqrt(k mRef)`, где `mRef = mA/2` на последнем Restart. Изменение массы B не перенастраивает c; изменение k/ζ пересчитывает c с прежней опорной массой.

Изменение массы/радиуса меняет инерцию B без телепортации. Изменение типа/длины очищает историю решателя. Числовые поля прицепа сохраняют набираемый текст; значение применяется при выходе из поля или по Enter. Пустое, нечисловое или выходящее за диапазон поле при этом отклоняется с ошибкой, прежнее значение сохраняется. Слайдер и кнопки массы применяют значение сразу и снимают ошибку; внешний сброс или пресет заменяет черновик принятым значением. Если размеры/новая длина несовместимы с текущим составом, показана причина и нужен Restart; подобрать подходящие размеры, затем перезапустить. Поиск свободного старта локальный, карта не изменяется.

## Ограничения и проверка

Линия сцепки не имеет коллайдера и может пересекать препятствие. Для A/B, стен и статических кругов используется общий непрерывный расчёт; орбы остаются штатными дискретными контактами. Ограниченный расчёт при отказе сохраняет последние валидные тела и показывает причину. Большой интервал кадра (>250 мс) требует явного продолжения.

Стартовый пресет BonkRace v0.3 имеет массу A 40 кг и большую штатную тягу. В QA некоторые сочетания давали скорости до 2000 м/с; диагностический диапазон `outsideSpeedRange` начинается выше 100 м/с. Сохранение конечных чисел и отсутствие проникновений в этих прогонах не доказывает физическую точность на 2000 м/с. Существующие проверки CCD включают относительную скорость 200 м/с. Для спокойного подбора параметров можно уменьшить тягу через штатную панель. Числа и методика приведены в [приёмке](reports/u2-tuglab-v0.1-acceptance.md).

Запись, повтор, импорт/экспорт, отдельные сцены доставки и управление отдельными двигателями исключены из текущего объёма оператором. Реальный Android-планшет ещё не проверен; имитация касания в Chrome этого не заменяет. Измерение производительности относится только к указанной среде QA.

## Воспроизведение QA и передача

```bash
npm run build
npm run test:tuglab
npm run typecheck:tuglab
npm run qa:tuglab:matrix
npm test
npm run build:lab --workspace=client
npm run check-version
npm run build:tuglab
```

`qa:tuglab:matrix` сохраняет матрицу в `.cache/tuglab-qa/matrix.json`. Для браузерной QA установить Playwright во внешний временный каталог, не в продуктовые зависимости, и указать `PLAYWRIGHT_MODULE` и при необходимости `CHROME_PATH`. `npm run qa:tuglab:browser` самостоятельно поднимает временный HTTP-сервер, проверяет корень/вложенный путь/BonkLab, снимает два размера и измеряет 120 с настоящего RAF. По умолчанию Chrome без окна; `TUGLAB_HEADLESS=0` включает окно, `TUGLAB_PERF_SECONDS=0` оставляет только smoke. Результаты и PNG — `.cache/tuglab-qa/`. Проверка физического планшета остаётся отдельной.

Отдельный workflow `TugLab checks and artifact` работает на PR, включая stacked PR с базой `docs/u2-tuglab-spec-v0.1`, и по ручному запуску. Он только проверяет и прикладывает архив/контрольную сумму/QA evidence; сайты не публикует. В CI выполняется browser smoke, а 120 с performance — локальная проверка приёмки.

Адресная регрессия числового ввода проверяет настоящие клавиши, фиксацию по Enter/blur и снятие ошибки: `TUGLAB_URL=http://localhost:5195/ node tests/tuglab/ui-numeric.cjs`. Перед запуском собрать TugLab и обслуживать `client/dist-tuglab` отдельным временным HTTP-сервером; адрес указать в `TUGLAB_URL`. Используются те же внешние Playwright/Chrome.

Публикация использует существующий GitHub Pages репозитория `bonk-race`: BonkLab остаётся на `https://komleff.github.io/bonk-race/`, TugLab получает `https://komleff.github.io/bonk-race/tuglab/`. Workflow `Deploy BonkLab to GitHub Pages` собирает обе оболочки и переносит TugLab в подпапку `tuglab` общего Pages artifact после завершения обеих сборок. В PR проверяется сборка этого же artifact; публикация разрешена только при push в `main` или ручном запуске из `main`.
