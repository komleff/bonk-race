# TugLab на tuglab.u2game.space

Архивная альтернатива: текущая поставка использует GitHub Pages `bonk-race/tuglab/`, см. [руководство](../TugLab-Guide.md).
Ниже сохранён прежний план VPS; он не входит в текущую задачу публикации и не требует действий.

Статус на 3 октября 2026: схема подготовлена по исходникам U2; сервер агентом не изменялся. DNS уже разрешается в `83.217.202.233`, HTTPS пока не открывается. Сборка и публикация учитываются отдельно в Beads `bonk-race-tow.5` и `.7`.

## DNS

В зоне `u2game.space`: `A`, имя `tuglab`, адрес `83.217.202.233`, TTL 300/Auto. A-записи apex, play и tuglab совпадают. Для начала достаточно DNS-only. При наличии AAAA он должен вести на этот же готовый сайт по IPv6; конфликтующий AAAA нужно исправить.

## Одноразовое добавление сайта в U2

В репозитории U2 подготовить отдельный PR с двумя дополнениями. Прежние сайты и параметры игрового сервера сохраняются.

Добавить блок в `Caddyfile`:

```caddyfile
tuglab.u2game.space {
    root * /var/www/tuglab.u2game.space/current
    encode zstd gzip
    header Cache-Control "no-cache, must-revalidate"
    file_server
    log
}
```

Добавить в `services.caddy.volumes` файла `docker-compose.prod.yml`:

```yaml
- /var/www/tuglab.u2game.space:/var/www/tuglab.u2game.space:ro
```

Нужно монтировать родительский каталог, чтобы переключение `current` было видно внутри контейнера. Не монтировать отдельно ссылку или конкретный release. Статика TugLab не требует U2 API, Unity-файлов, WebSocket proxy или SPA fallback. Не переносить правила `.gz` и заголовки Unity из apex.

[Caddy file_server](https://caddyserver.com/docs/caddyfile/directives/file_server) обслуживает index.html из выбранного root. [Automatic HTTPS](https://caddyserver.com/docs/automatic-https) выдаёт сертификат и включает HTTP→HTTPS при корректном DNS и доступных портах 80/443.

## Каталог и применение — оператор

На VPS оператор создаёт отдельный обычный каталог `/var/www/tuglab.u2game.space`; внутри — `releases/<release-id>/`, относительные ссылки `current` и `previous` на проверенные release. Сборка содержит только `index.html` и свои статические ресурсы, без исходников, node_modules, ключей и ссылок. Caddy должен иметь чтение файлов и проход каталогов. Первоначально `current` может указывать на простой placeholder, пока игровой artifact не принят.

Перед применением оператор сохраняет текущие Caddyfile/compose, проверяет отсутствие drift и записывает ID/StartedAt `u2-server`. Конфигурацию валидирует на используемом образе `caddy:2-alpine`. Добавление нового bind-mount требует пересоздания только Caddy, поэтому возможен короткий перерыв HTTPS общего прокси. `u2-server` пересоздавать не требуется.

В U2 предусмотрен config-only порядок `scripts/caddy-config-only-vps.sh`: оператор сначала делает dry-run на согласованных ref/base, затем apply. Агент не запускает его: [ADR-0030 U2](https://github.com/komleff/u2/blob/main/docs/architecture/ADR-0030-AI-Deploy-Via-CI-Trigger.md) запрещает агентам production SSH. Применение конфигурации — отдельное действие оператора после review U2 PR.

## Доставка и откат

После принятия standalone artifact задачи `.5` доставка заменяет только выбранный release внутри нового каталога. Новый release проверяется целиком до атомарного переключения относительной ссылки `current`; прежняя цель сохраняется как `previous`. Откат переключает ссылку на прежнюю проверенную цель, без пересборки. Не удалять активный и предыдущий release; не копировать сборку в каталог apex/BonkLab и не использовать общий серверный deploy для статики.

Для автоматической доставки нужен отдельный workflow BonkRace, отдельный deploy user с доступом только к этому каталогу и новые environment secrets. Эти входы ещё не настроены. Имеющиеся U2 WebGL/server workflows имеют другой target и не подходят. Новый CI-путь сначала проходит отдельное согласование по ADR-0030; ключ остаётся в GitHub environment, агент его не получает.

После доставки оператор проверяет HTTPS `/`, правильную версию/commit сборки, загрузку всех ресурсов и игру. Затем проверяет прежние apex/download/test/relay/BonkLab, прежний ID/StartedAt `u2-server`, выполняет откат и возврат принятого release. Только реальные результаты этих проверок закрывают `.7`; наличие DNS или данного документа не считается публикацией.

При переключении release открытая вкладка может потребовать обновления страницы. Для первой ручной лаборатории это допустимо; бесшовная смена ресурсов отдельным требованием не заявляется.
