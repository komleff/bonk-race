# Sprint 1 — BonkRace MVP Playable Loop

**Дата:** 7 марта 2026
**Цель:** Замкнуть игровой цикл MVP: авторизация → загрузка трассы → гонка → отправка результата → лидерборд → рестарт
**Ветка:** `sprint-1/mvp-loop`
**Базовая ветка:** `main`

---

## Контекст

Проект BonkRace (форк Slime Arena) имеет 95% инфраструктуры для MVP: клиентская физика, рендер, ghost-система, серверные эндпоинты, БД-миграции. Осталось **соединить компоненты** и **исправить ориентацию трассы** (GDD требует вертикальное движение вверх, а текущий Starter Circuit — горизонтальный овал).

Текущее состояние: клиент загружает трассу через Vite proxy, рисует и управляет блобом. Но результат не отправляется, ghost-и не загружаются, авторизации нет.

### Фаза 1: DevAuth на клиенте (P1)
> `bonk-race-nda` — DevAuth flow для локального тестирования

**Файлы:**
- `client/src/raceMain.ts` — добавить получение/сохранение dev-токена
- `client/src/api/metaServerClient.ts` — уже поддерживает Bearer token из localStorage

**Что:**
1. При запуске в dev-режиме: если нет токена в localStorage, вызвать `/api/v1/auth/dev-login` (или вшить `dev:player1` как Bearer)
2. Сохранить токен в localStorage — `metaServerClient` подхватит автоматически
3. Все последующие запросы пойдут авторизованными

**Зачем:** Без авторизации невозможно сохранять результаты (submit-run привязан к userId).

### Фаза 2: Submit результата (P1) — КРИТИЧЕСКИЙ ПУТЬ
> `bonk-race-3yn` — POST /api/v1/runs/submit

**Файлы:**
- `client/src/raceMain.ts` — вызвать submit после финиша
- `server/src/meta/routes/runs.ts` — эндпоинт уже существует

**Что:**
1. После перехода в фазу RESULTS, собрать данные: `{ trackId, finishMs, replayData (packed ghost), inputHash }`
2. POST через `metaServerClient.post('/api/v1/runs/submit', data)`
3. Обработать ответ (позиция в лидерборде, медаль)

**Зачем:** Центральная точка: разблокирует ghost, leaderboard и medals.

---

### Фаза 3: Загрузка ghost-соперника (P1)
> `bonk-race-549` — Ghost система: запись + воспроизведение

**Файлы:**
- `client/src/raceMain.ts` — fetch ghosts перед стартом гонки
- `client/src/game/GhostPlayer.ts` — уже реализован
- `client/src/game/GhostRecorder.ts` — уже реализован

**Что:**
1. После загрузки трассы: GET `/api/v1/ghosts?trackId=X`
2. Распаковать replay через `GhostRecorder.unpack()`
3. Создать `GhostPlayer` и передать в game loop
4. Рендерить полупрозрачный блоб-ghost рядом с игроком

**Зачем:** Ghost — ключевая механика соревнования (GDD §5).

### Фаза 4: Лидерборд + медали (P2)
> `bonk-race-a6g` + `bonk-race-tb9`

**Файлы:**
- `client/src/raceMain.ts` — UI результата с позицией и медалью
- Серверные эндпоинты уже существуют

**Что:**
1. После submit получить позицию в лидерборде
2. Показать на экране результатов: время, медаль (Bronze/Silver/Gold), позицию
3. Кнопка «Retry» для мгновенного рестарта (GDD §2: <0.5 сек)

**Зачем:** Замыкает петлю «ещё одна попытка».

---

### Фаза 5: Вертикальная трасса (P1) — НОВАЯ ЗАДАЧА
> Нужно создать в Beads

**Файлы:**
- `server/src/meta/data/trackPresets.ts` — заменить Starter Circuit на коридорную вертикальную трассу
- `client/src/raceMain.ts` — камера: scroll по Y вместо X
- `shared/src/trackConfig.ts` — проверить, что `startPos`/`finishPos` поддерживают вертикальную ориентацию

**Что:**
Текущий Starter Circuit — горизонтальный замкнутый овал. По GDD §4.1 трасса должна быть:
- Коридорная (точка A → точка B), не замкнутая
- Вертикальная ориентация (игрок едет **снизу вверх**)
- Портретная камера (top-down, portrait)
- 30-90 секунд оптимального прохождения

Нужно:
1. Создать новый пресет: вертикальный коридор ~800×3000, чекпоинты снизу вверх
2. Адаптировать камеру (камера следует за блобом по Y-оси с опережением)
3. Проверить, что checkpoint-система работает с линейной трассой (не loop)

**Зачем:** Фундаментальное расхождение с GDD. Без этого MVP не соответствует дизайн-документу.

## Порядок выполнения (граф зависимостей)

```
Фаза 0 (fak)  ──────────────────────────────────────┐
                                                      │ параллельно
Фаза 5 (вертикальная трасса) ────────────────────────┤
                                                      │
Фаза 1 (DevAuth) ───┐                                │
                     ├──→ Фаза 2 (Submit) ──→ Фаза 3 (Ghost)
                     │                    └──→ Фаза 4 (Leaderboard + Medal)
```

- Фазы 0 и 5 можно делать параллельно с фазами 1-2
- Фаза 2 блокирует фазы 3 и 4 (существующие зависимости в Beads)
- Фаза 1 блокирует фазу 2 (без авторизации submit не работает)

## Новые задачи для создания в Beads

| Задача | Тип | Приоритет | Зависит от |
|--------|-----|-----------|------------|
| Вертикальная коридорная трасса (GDD §4.1) | feature | P1 | — |
| Мгновенный рестарт после финиша/смерти (GDD §2) | task | P1 | — |
| Виртуальный джойстик для мобильных (перенос из main.ts) | task | P1 | — |

> **Джойстик:** В `main.ts` (Slime Arena) есть полноценная реализация adaptive-джойстика с touch-событиями, deadzone, follow-speed и т.д. В `raceMain.ts` (BonkRace) есть только pointer-based управление мышью. Нужно перенести джойстик из `main.ts` → `raceMain.ts`, адаптировав под BonkRace (вертикальная ориентация, портретный режим).

## Критерии готовности MVP

- [ ] Игрок открывает http://localhost:5173 → авторизуется автоматически (DevAuth)
- [ ] Загружается вертикальная коридорная трасса (не овал)
- [ ] Управление: мышь drag-to-steer, блоб едет **вверх**
- [ ] Камера следует вертикально за блобом
- [ ] После финиша: результат отправляется на сервер
- [ ] Отображается время, медаль, позиция в лидерборде
- [ ] Ghost предыдущей попытки виден на трассе
- [ ] Кнопка Retry → мгновенный рестарт (<0.5 сек)
- [ ] `npm run build` проходит без ошибок

## Верификация

1. `npm run build` — сборка shared → server → client
2. Запустить meta-server: `cd server && npx ts-node-dev -r tsconfig-paths/register src/meta/server.ts`
3. Запустить клиент: `npm run dev:client`
4. Открыть http://localhost:5173 → проехать трассу → убедиться в submit + ghost + leaderboard
5. `node server/tests/tracks-smoke.test.js` — smoke-тест треков
