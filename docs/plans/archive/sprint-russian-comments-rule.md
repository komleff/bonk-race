# План: Правило «комментарии на русском» + отчёты в PR

## Контекст

Две проблемы:

1. ИИ-разработчики пишут комментарии в коде на английском — правило есть только в `.agents/AGENT_ROLES.md:360`, основные точки входа его не содержат.
2. В PR нет полной картины разработки — Developer-отчёты не всегда публикуются. Решение: PM публикует Developer-отчёты после каждого цикла кодирования.

Разные ИИ-модели читают разные файлы — дублирование между ними оправдано:

| ИИ-модель | Точка входа | Правило о русских комментариях |
| --------- | ----------- | ------------------------------ |
| Claude | `CLAUDE.md` → `CLAUDE-core.md` | Нет |
| Copilot/GPT | `.github/copilot-instructions.md` | Нет |
| Gemini/все | `AGENTS.md` | Нет |
| Все роли | `.agents/AGENT_ROLES.md` | Да (строка 360) |

## Часть 3: Developer-отчёты публикует PM (2 файла)

### 3.1 `.agents/AGENT_ROLES.md` — убрать обязанность Developer публиковать отчёт

**Секция «Публикация отчёта в PR (ОБЯЗАТЕЛЬНО!)»** (строки 512-568) — заменить на краткое указание:

**Было:** Полная секция (56 строк) с форматом, шаблоном и командой `gh pr comment`.

**Стало:**

```markdown
### Результат работы

После завершения кодирования Developer сообщает PM:
- Какие файлы изменены и почему
- Результаты `npm run build` и `npm run test`
- Какие замечания ревьюверов учтены (если исправление по review)

> PM публикует Developer-отчёт в PR. Developer не публикует отчёты в PR самостоятельно.
```

### 3.2 `.agents/PM_ROLE.md` — добавить обязанность публикации Developer-отчётов

**Файл:** `.agents/PM_ROLE.md`

**Место:** Секция «2.2 Делегирование Developer», после строки 131 (после «PM запускает автоматический review»).

**Добавить новый пункт 5 (текущий 5 → 6):**

```markdown
5. PM публикует Developer-отчёт в PR через `gh pr comment`:

   ```bash
   gh pr comment <PR-номер> --body "$(cat <<'EOF'
   <!-- {"reviewer": "opus", "iteration": N, "type": "developer_report"} -->

   ## Developer Report by [Модель] (Iteration N)

   ### Выполненные изменения

   | Файл | Изменение |
   |------|-----------|
   | `file.ts` | Описание |

   ### Тесты

       npm run build — OK
       npm run test — OK

   ### Учтённые замечания

   | Замечание | Статус |
   |-----------|--------|
   | [P1] file.ts:123 — описание | Исправлено |

   EOF
   )"
   ```
```

**Также:** В секцию «Критерии качества» (строка 908-927) добавить:

```markdown
- Developer-отчёт опубликован в PR после каждого цикла кодирования/исправлений
```
