# Фикс: неравномерный след за персонажем после оптимизации drawTrail()

## Контекст

После однопроходной оптимизации `drawTrail()` (коммит c9e7ff0, PR #25) при равномерном движении за персонажем остаётся визуально неравномерный след — рваные переходы прозрачности вместо плавного затухания.

Оптимизация заменила per-point рендеринг (600 `fill()` за кадр) на однопроходный алгоритм с квантованием в 10 групп прозрачности. Визуальная регрессия — побочный эффект.

---

## Корневая причина

**Итерация кольцевого буфера в неправильном порядке.**

`drawTrail()` обходит `trailBuffer[0..trailCount-1]` линейно. Но в кольцевом буфере после заполнения точки НЕ упорядочены по возрасту:

```
Буфер: [новые...] [trailHead → старые...]
Индексы: 0  1  2  ...  trailHead  trailHead+1  ...  599
Возраст: средний       самый старый                    молодой
```

Линейный обход перескакивает между группами прозрачности:
- `pt[0]` → группа 3 → beginPath, fill
- `pt[1]` → группа 7 → beginPath, fill
- `pt[2]` → группа 3 → beginPath, fill (ещё раз!)

**Результаты:**

1. **Пространственная неравномерность**: точки одной группы разбросаны по разным `fill()` вызовам. При перекрытии кругов — двойное альфа-композитирование (темнее, чем должно быть).

2. **Нарушение z-порядка**: старые (тусклые) точки рисуются ПОВЕРХ новых (ярких), создавая обратный эффект затухания.

3. **Квантование на 10 уровней**: каждый шаг — 0.06 альфа (при baseAlpha=0.6), видимые полосы.

## Исправление

**Файл:** [LabRenderer.ts](client/src/lab/LabRenderer.ts), метод `drawTrail()` (строки 491–538)

### Изменение 1: Итерация в порядке возраста (от старых к новым)

Заменить линейный обход:
```typescript
// БЫЛО:
for (let i = 0; i < this.trailCount; i++) {
    const pt = this.trailBuffer[i];
```

На обход по возрасту:
```typescript
// СТАЛО:
const isFull = this.trailCount >= TRAIL_MAX_POINTS;
for (let j = 0; j < this.trailCount; j++) {
    // Кольцевой буфер: trailHead = самая старая точка (следующая на перезапись)
    // Растущий буфер: точки уже в порядке 0→trailCount-1
    const i = isFull ? (this.trailHead + j) % TRAIL_MAX_POINTS : j;
    const pt = this.trailBuffer[i];
```

**Почему это работает:**
- `trailHead` указывает на следующую позицию записи = самая старая точка
- Обход от `trailHead` вперёд (с оборотом) даёт порядок: старые → новые
- Группы прозрачности меняются монотонно: 9→8→...→1→0
- Для моноцвета: ровно 10 (или OPACITY_LEVELS) переходов → минимум `fill()` вызовов
- Z-порядок правильный: тусклые (старые) рисуются первыми, яркие (новые) поверх

### Изменение 2: Увеличить OPACITY_LEVELS с 10 до 25

```typescript
// БЫЛО:
const OPACITY_LEVELS = 10;

// СТАЛО:
const OPACITY_LEVELS = 25;
```

- Шаг прозрачности: 0.06 → 0.024 (при baseAlpha=0.6) — бандинг незаметен
- Для моноцвета: 25 `fill()` вызовов — всё ещё 24× лучше, чем 600
- Для drift/rainbow: число вызовов не меняется (каждая точка уникальна по цвету)

## Что НЕ трогаем

- `pushTrailPoint()` — кольцевой буфер работает корректно
- `ageTrail()` — корректно стареет все активные точки
- `calculateTrailColor()` — не связано с проблемой
- `BonkLab.ts` — физика и интерполяция не затронуты

---

## Верификация

1. `npm run dev:client` → `/lab`
2. Включить след (моноцвет), двигаться равномерно → след должен плавно затухать без рывков прозрачности
3. Переключить на drift/rainbow → цвета должны ложиться гладко
4. Смерть/респаун → след корректно сбрасывается
5. Performance: подтвердить, что число draw calls для моноцвета ~25 (не 600)
