# Поезд с двумя тягачами в U2TagLab

Поезд A–B–C добавляется в существующую космическую версию U2TagLab: A ведёт игрок, B пассивен, C управляется ограниченным ассистентом. Полёт проходит на текущем маршруте со станциями, обломками, подвижными астероидами и полями. Состав A–B остаётся доступен в той же оболочке.

## Запуск

Используйте Node 20 и установленные зависимости проекта:

```sh
npm run dev:u2taglab
```

Откройте `/u2taglab.html` на порту 5175. Если этот порт занят другим checkout, задайте свободный порт:

```sh
npm run dev:u2taglab --workspace=client -- --port 5178
```

Готовая общая сборка сохраняет BonkLab, TugLab и U2TagLab:

```sh
npm run build:pages
python3 -m http.server 5177 --bind 0.0.0.0 --directory client/dist-pages
```

Откройте `/u2taglab/`; для планшета в той же сети — `http://192.168.68.65:5177/u2taglab/`. Сервер должен оставаться запущенным. Финальный отчёт приёмки указывает фактически проверенный SHA.

## Полёт по маршруту

1. Поставьте текущий полёт на паузу и выберите состав A–B–C в существующем интерфейсе. Настройки состава создают безопасное начало на той же карте с исходным seed и плотностью.
2. Проверьте три корпуса и две пружины: хвост A/нос B, хвост B/нос C. Масштаб и экранная опора A сохраняют прежнее поведение U2TagLab: камера учитывает A–B, положение C не уменьшает вид. Радар показывает C вместе с текущими препятствиями и полями.
3. Начните полёт. WASD/стрелки задают мировое направление, мышь — направление от A к курсору при удержании. На телефоне используйте существующий сенсорный джойстик.
4. Пройдите участок маршрута между препятствиями, постепенно поворачивая и тормозя. Столкновения и поля действуют на все тела, подвижные астероиды участвуют в общей физике. Пружины не оборачиваются вокруг препятствий; оставляйте место всему составу.
5. Включите нужный режим C. Передний FA и тормоз A сохраняют прежнее управление; заднее удержание тормоза независимо и доступно вторым пальцем.
6. Проверяйте команды C и нагрузки обеих связей. Расцепка AB или BC меняет только выбранную связь и сразу выключает ассистент. После захвата явно выберите режим C, чтобы вернуть помощь.
7. На паузе измените C, массу B и отдельные модули/длины AB и BC. Изменение массы не усиливает двигатели и не меняет фиксированные k/c. Неподходящие настройки должны показывать причину и сохранять текущий состав.
8. Restart возвращает начало текущего маршрута; seed/плотность выбираются прежними инструментами U2TagLab. Для завершения маршрута поездом все присутствующие тела должны пройти финиш. Выбор A–B возвращает прежний двухтелесный режим.

При потере фокуса, сворачивании вкладки или отмене ввода полёт ставится на паузу, удержания освобождаются и команды C обнуляются. Ввод в поля настроек не должен пилотировать корабль. Одиночный Step проверяет один принятый физический тик.

## Ассистент

| Режим C | Ретро | Боковая тяга / момент |
|---|---|---|
| Накат | 0 | 0 |
| Страховка | до 25% × g | до 50% × g |
| Помощь при торможении | до 100% × g по задержанному запросу; иначе до 25% × g | до 50% × g |

Маршевая тяга C равна нулю. Начальные g=100%, задержка0.25 с; g=0 обнуляет все команды. Наблюдения и запрос торможения причинные: повторные попытки решателя не ускоряют реакцию. При текущем BC ≥1.5l₀ ретротяга блокируется. C не меняет координаты/скорости напрямую и не включает отдельный FA.

Обычный полёт использует игровой адаптер без обязательного растущего журнала и без автоматического завершения через60с после тормоза. Начальная ссылка поезда открывает новый опыт на паузе; прежние A–B ссылки сохраняют свои схемы. Численные записи/replay/сравнения реализованы в отдельных проверочных библиотеках; прежний отдельный dashboard отменён уточнением оператора и не является интерфейсом этой поставки.

## Границы проверки

Интеграция и её адресная приёмка описываются в отдельном отчёте по актуальному SHA. Прежние отчёты отдельной оболочки сохраняются как история и не подменяют полёт в U2TagLab. Реальный Android проверяется по [сценарию](TugLab2-Android-check.md); эмуляция устройства не закрывает этот этап.

Предварительные торможения прежнего адаптера сохраняют отрицательные результаты: на40м/с уменьшение пикового угла сопровождалось увеличением бокового ухода и пути; стандартные40/80м/с достигли тайм-аута. Ассистент не гарантирует безопасную остановку для всех масс, скоростей и маршрутов.
