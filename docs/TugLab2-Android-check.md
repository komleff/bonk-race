# Поезд U2TagLab — проверка на физическом Android

Этот сценарий не является результатом проверки. До запуска на реальном устройстве `bonk-race-tug2.5` и Android-часть AC-13 остаются открытыми. Desktop Chrome и эмуляция сенсорного экрана учитываются отдельно.

## Запуск

На компьютере с Node20 из корня checkout:

```sh
npm ci
npm run build:pages
python3 -m http.server 5177 --bind 0.0.0.0 --directory client/dist-pages
```

Планшет и компьютер должны быть в одной сети. Открыть `http://<LAN-IP-компьютера>:5177/u2taglab/` в Chrome. Для текущего стенда адрес — `http://192.168.68.65:5177/u2taglab/`. Сервер должен оставаться запущенным. Записать модель устройства, Android/Chrome, размер экрана, ориентацию, исходный SHA сборки и дату.

## Сценарий, около пяти минут

1. На существующей странице U2TagLab поставить полёт на паузу и выбрать A–B–C. Проверить три корпуса и обе пружины на текущем маршруте. Панель не должна перекрывать пилотирование.
2. Начать полёт. Джойстиком дать направление вправо, затем вверх, пройти между препятствиями. Все тела движутся и видны; камера вмещает состав, радар показывает C. Повторить в портретной и альбомной ориентации.
3. В «Накате» команды C нулевые. Выбрать «Страховку», g50%, задержку1с; проверить видимые ограниченные команды. При g0 все команды нулевые.
4. Выбрать «Помощь при торможении», задержку2с. Одним пальцем вести A, другим удерживать задний тормоз. Отпустить его; увеличенный предел ретро следует задержанному запросу, а режим сам по себе не включает полный ретро.
5. Во время удержания свернуть вкладку/приложение. После возврата — пауза, ввод и команды C сброшены. Повторить отмену касания; возобновление не включает старое удержание.
6. Независимо расцепить/захватить AB и BC. В движении расцепка сразу выключает C; захват не возвращает помощь до явного выбора режима.
7. На паузе проверить C, отдельные AB/BC и массы B/A10%/1000%. Настройки либо дают безопасный новый старт, либо сохраняют прежний состав с понятной причиной отказа.
8. Restart сохраняет выбранный маршрут/seed. Сохранить начальную ссылку ABC и открыть её: новый состав на паузе. Проверить старую A–B ссылку и возврат к обычному A–B.

Записать модель устройства, Android/Chrome, ориентации, дату, SHA, выполненные шаги и фактические ошибки. При отказе сохранить снимок/видеозапись и сообщения. Закрывать Android-критерий по HTTP-ответу или эмуляции нельзя.
